## 评估（日志实证）

### ① 飞过去：目标在 2 秒内就到了，之后 70 秒都在盒外打转

```
03:59:20.816 [飞行跟随] 飞向指定坐标（58.4 格），背上鞘翅追过去
03:59:22.602 [飞行跟随] 进到主人 3.6 格内，解除推进矢量（水平速度 1.64 → 0）
03:59:27.692 [飞行跟随] 结束（目标点 4.5 格，原因=5 秒没拉近（判追不上）…）
03:59:27.742 [飞行跟随] 飞向指定坐标（4.5 格），背上鞘翅追过去
…（此后每 5 秒重复一次：解除推进矢量 → 结束（追不上）→ 重新起飞）
04:00:30.742 [飞过去] 已到达目标点附近（5×5×5），落点 (-67.4, -50.2, -25.0) 目标 (-67.9, -48.0, -24.7)
```

- 起飞日志写的是「58.4 格」，1.8 秒后「解除推进矢量」那行已经只有 **3.6 格**——距离是到目标点的，
  不是到主人的（那行措辞用的是旧的 `isGoto` 判断，所以误写成「主人」）。
- 随后她一直在目标点 **4–6 格**处循环：`endRadius()` 默认 5 格，一进 5 格 `tick` 就把速度清零；
  而到点盒只有 ±2.5 格。**刹车圈比到点盒大**，她永远差那 2.5 格。
- 与此同时「5 秒没拉近」收手对 travel 同样生效：清零后 5 秒没有新进展 → 收手 →
  冷却后重启 → 再进 5 格再清零。玩家看到的正是「减速了，但状态一直解不掉」。

### ② 直升机：`生效=true` 却 `分支=跟随主人`，目标点跟着主人涨

```
04:07:02.123 [航迹飞行] home=true 绑定=true 生效=true 说明=生效 分支=跟随主人 目标=(-291.0, -42.5, -265.7)
04:07:27.093 [航迹飞行] … 分支=跟随主人·近距悬停 目标=(-263.1, -29.7, -235.6)
04:07:32.091 [航迹飞行] … 分支=跟随主人·近距悬停 目标=(-263.1, -10.7, -235.6)
04:07:32.895 [模组坐骑] 飞行档 … 跟随档(比主人高3格) 高差=3 竖直速度=0.19
```

- 按代码顺序，`patrolFlight=true` 时分支只可能是 `航迹` 或 `航迹·本拍无点→悬停`，
  不可能是 `跟随主人`。日志能同时出现这两项，唯一解释就是**后者把前者覆盖了**。
- 读代码坐实：`RideBindManager` 的「跟随主人」那一段写在 if/else 链**外面**，
  每拍无条件执行——「飞过去 / 航迹 / 航迹悬停」刚算出的 `air` 全部被改写成
  `hoverAt(owner.x, owner.z, owner.y)`。目标 Y 于是等于主人 Y + 3，
  主人往上一飞、目标跟着涨，就是日志里 `-42.5 → -29.7 → -10.7` 与 `高差=3` 的永久爬升棘轮。

## 改动

### ① 飞过去收尾（两树 `MaidFlightFollowBehavior`）

- `tick`：开头先取 `travelNow`。travel 期间**不做** `endRadius()` 刹车，
  也**不参与**「5 秒没拉近」判定；改为每秒一行
  `[飞过去] … 飞向目标点 距离=… 水平速度=… 竖直速度=…`。
- `canStillUse`：travel 时忽略/清掉上一趟遗留的 `STOP_NOW`；
  新增到点消费：`consumeArrival` → `ARRIVAL_STOP` + `原因=已到达目标点` → 本趟收手。
  下一拍不会因为 travel 已被清掉而回落成「跟随主人」重新起飞。
- `stop`：到达收手时结束日志写 `结束（已到达目标点，原因=已到达目标点；…）`，
  不再误报「追主人 N 格」。

### ② 到点判据（两树 `MaidTravelTarget`）

- 包围盒从 ±2.5 放宽到 **±5 格（10×10×10）**：既然实际刹车发生在 5 格，
  到点盒就必须不小于它，否则「减速」与「结束」永远错位。
- 兜底：已经在 **8 格内停稳 3 秒（60 tick）** 也算到——绕圈/悬停时不会永远差几格。
- 到点后留一个一次性「刚到达」标记（200 tick 有效），供飞行行为收手用；
  日志与聊天栏的「本次飞行结束」保持 R1119 口径。

### ③ 直升机分支（两树 `RideBindManager`）

- 把「跟随主人」整段收进 if/else 链的最后一个 `else`。
  现在的优先级是：接敌 → 飞过去 → 航迹 → 航迹·本拍无点→悬停 → 航迹未生效→悬停 →
  机上有人→悬停 → **最后才是跟随主人**。
- 这样 `[航迹飞行]` 里的 `分支=` 与真正喂给驾驶层的 `目标=` 才一致；
  `生效=true` 时实际驱动的一定是航迹点，不再被主人坐标覆盖。

## 边界

- 到点后目标即清除；想再飞一次要重新点「飞过去」。
- 「8 格内停稳 3 秒」只在她**已经进到 8 格**时计时，不会在远处提前结束。
- 直升机绑了航迹但未闭环/点数不足时仍是悬停等补完，不会追主人。
- 物理上飞不了（没有鞘翅/推进剂）仍然不飞——这是"她做不到"，不是阻挠。
- 版本号仍为 **1.3.3**，同号重打；发布素材等验收后再写。

## 验收

1. **飞过去到点即结束**：点「飞过去」后搜 `[飞过去]`，应看到每秒一行的
   `距离=… 水平速度=…`；距离进到 5 格内很快出现
   `已到达目标点附近（±5 格包围盒）` 和聊天栏「本次飞行结束」，
   随后 `[飞行跟随] 结束（已到达目标点，原因=已到达目标点…）`，**不再**每 5 秒
   重复 `解除推进矢量` / `结束（追不上）`。
2. **直升机沿轨**：绑闭环航迹后搜 `[航迹飞行]`，应看到 `生效=true 说明=生效 分支=航迹`
   或 `分支=航迹·本拍无点→悬停`，**不再出现** `生效=true 分支=跟随主人`；
   `[模组坐骑]` 的 `距目标/高差` 应围绕航迹点（航迹点的 y），不再出现
   `高差=3` 恒定 + `竖直速度` 持续为正的爬升。
3. **home 跟随**：直升机开 home + 闭环航迹后，机身应按航迹绕行；把主人带到机舱外观察，
   目标点仍应是航迹点而不是主人坐标。
