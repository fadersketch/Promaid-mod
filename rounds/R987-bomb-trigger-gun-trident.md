# R987 路 轰炸/TNT 触发点补一条与打法无关的判据（枪械 / 三叉戟）

## 排班

1. 现象：战斗状态下该有的「投 TNT + 放末地水晶 / 重生锚 / 床」在**枪械模式**与**三叉戟模式**里不触发。
2. 根因（读写实证）：所有攻击模式共用的入口 `BombTntTick.tickCombatTnt` 把「她刚打完一记」挂在
   **攻击冷却记忆 `ATTACK_COOLING_DOWN` 由无到有**的边沿上——那份记忆是 TLM 近战 / 弓弩行为自己写的，
   枪械（`TaskGunAttack`）与三叉戟这类任务的攻击**不写它**，于是边沿永不出现，②整段空转：
   既不轰炸起手，也不投 TNT（而近战 / 弓箭模式一切正常，正好对上"部分模式不触发"）。
3. 修法：补一条**与打法无关**的判据 —— 目标身上「最近打它的人」是不是一条新鲜记录。
4. 两树镜像 → 编译 → 构建 → 部署 4 实例 → 台账。

## 需求 / 来源

- 「很早之前我提到过，女仆会在任何一个算作战斗的状态下投掷 TNT / 放置末影水晶和重生锚。
  但在刚刚运行的游戏里面，并没有做到这一点。就像枪械模式和三叉戟模式就没能触发这个效果。」
  （对照 实测五百九十二「轰炸推广到所有攻击模式」——那次改的是"哪些任务算战斗"，这次补的是
  "哪一下算打完一记"。）

## 改法

### `BombTntTick.tickCombatTnt` 新增判据 ③′（两树镜像）

- 位置：② 之后、④（TNT 那一发）之前。
- 判据：`target.getLastHurtByMob() == maid`（目标身上"最近伤害它的人"就是她）
  + 该时间戳在 `HIT_TRIGGER_TICKS = 40`（2 秒）内 + 与上次见过的时间戳**不同**（真的是新的一下）。
  第一次观察到的旧记录不会误触发（时间戳早过期），同一下也不会重复触发（时间戳去过重）。
- 命中后与 ② 完全同效：登记 `TNT_ARMED` → 先试轰炸起手（黑曜石+水晶 / 重生锚+萤石 / 床）；
  起手成功即 `return` 交相位收尾；未起手则自然落到 ④ 投 TNT。
- 限流照旧：`TNT_NEXT`（最短间隔 10 秒）、`ARMED_TIMEOUT`、相位互斥、`forbidsBombing`（扫帚）、
  `isCombatTask`（非战斗任务不打扰）、傀儡模式让位——一条都没动。
- 新增 `MaidBombing.LAST_HIT_TS`（女仆 UUID → 见过的目标挨打时间戳），`forget` / `clearAll` 一并清。

## 验收

- 枪械模式：她打中第一下之后，只要背包里有料（TNT + 打火石/烈焰弹，或水晶/重生锚/床那一套），
  就会按既有节奏轰炸起手 / 投 TNT（10 秒最短间隔）；此前这些模式一下都不出手。
- 三叉戟模式（近战与投掷两条路）：同上。
- 近战 / 弓弩模式行为一字不变（② 那条边沿照旧，两条判据同一条闸、不重复出手）。
- 扫帚模式、非战斗任务、傀儡模式照旧不投。

## 边界

- ③′ 只加"哪一下算打完一记"的判据，**不动**任何材料判据 / 落点判据 / 爆炸口径 / 回收链。
- 依赖"她的伤害记在她名下"（`lastHurtByMob`）：若某个第三方枪械把伤害归给别的实体，
  那一条仍不触发——这种情况要靠后续日志再补（本轮先覆盖 TLM 自家枪械任务与三叉戟）。
- 目标必须在 `legalThrowTarget` 认定的合法范围内（友军 / 主人不算），与旧口径一致。
