## 评估
- **跑道**：只改记录/工具（判定依据：不产新字节）。
- **两条 WARN 的根因**：
  1. **13 个旧 jar 未登记**：`check_workflow.check_registry()` 会把 `patched/*.jar` 里「不是现版本、又不在登记表」的 (版本, 加载器) 聚合成一条 WARN；1.1.0 ~ 1.2.5 这些从来没进过表 → 常年挂着。
  2. **`promaid-1.2.4.jar` 不在归档里**：它是 1.2.4 上线平台与 GitHub release 的那一份（PUBLISH_GUIDE A.5），但 1.2.5 起文件命名改成 `-forge-1.20.1`，归档里只剩改名后重打的那份（`cbbd2e9a…52c0dd`，已单独登记为 `archived`），原名的字节**已不在本机**——核对不了，属于"不能归"。
- **同类点清单与处置**：登记表里另一条 `published-overwritten`（1.2.4 neo）**没有任何告警**——因为 `check_registry()` 只对 `status == 'published'` 的行做哈希核对，`published-overwritten` 走的那个 WARN 分支（脚本 171–173 行）实际到不了。**本轮不动它**（见「边界」）。
- 先查过 `ARCHITECTURE-SWITCHES.md`（无开关）、`BUG_DEBT.md` / `TECH_DEBT.md`（无同项；这两条只记在轮次「边界」里）。

## 改法
1. **补登记 13 行**（`rounds/RELEASES.tsv`，插进版本序里）：1.1.0（forge/neoforge）、1.1.1、1.2.0 ×2、1.2.1 ×2、1.2.2 ×2、1.2.3 ×2 插在 1.2.4 那三行之前；1.2.5 ×2 插在 1.2.4 之后、1.3.0 之前。状态一律 `archived`，**哈希取实测值**（`前8位…后6位`），日期取该文件的**落盘日**（不是编的），备注写明「补登记（实测九百五十七）：两个版本更新中途的产物，只记本地归档哈希（不主张是否上过平台）」。
2. **历史件缺文件 → 降级为打印**（`tools/verify/check_workflow.py`）：`published` 行的文件不在 `patched/` 时，若该行**不是现版本**，打印 `（历史件 … 不在归档，跳过核对；归档里同版本另有 …）` 后 `continue`；只有**现版本**缺文件才仍 WARN（那条真出事：现版本的字节必须能当场核对）。
3. **政策落文**：`rounds/RELEASES.tsv` 头部加一行（历史行能归就归；归档里没文件的已交付件不再告警）；`WORKFLOW.md` §5.3 加一段「能归就归」的定义、§5.4 的 WARN 条目补注（现版本必须登记；旧号能归就归）。
4. **现版本两行**各加一条 R957 条款（与 R955 同款：只挡行政务，jar 同字节）。
- **被否掉的方案**：①**删掉旧 jar / 裁掉旧行**（我先按字面理解成的那个意思）——开发者澄清后否掉：旧 jar 留着，"能归就归"指的是**登记**不是清理；②给 1.2.4 那条改状态（如 `archived`）来消 WARN——那会篡改一条 `published` 行对"平台上那份是什么"的记录，不动它，改机器口径更干净。
