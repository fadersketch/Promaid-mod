## 需求 / 来源

九百三十 已经把挖矿链路每条出口都变成一行日志。开发者按那条链路实测了一次，日志当场指出两件事：

1. **挖矿卡死有确凿的一条路径**（见下 `## 定位与改法 1` 的日志引用）——她顶着**一个够不着的挡路块**站了 16 秒，脚下高度一动不动，期间**零破坏进度**；最后只有"够不着超时"那一行把她救出来，然后她靠**收放（重新召唤）**才恢复正常。
2. **降落链路的观测盲点**是**我九百二十九 自己留下的**：新加的 `定跑道` 那一行与其余降落日志共用 `logDrive`（每坐骑一条、5 秒节流）——一条跑道到底有没有被规划出来，在日志里**看不见**（实测每 5 秒恰好只有一行降落日志，轮流说别的）。

所以本轮：挖矿**修**（把"卡住判据"补到那条漏掉的路上），降落**加日志**（给降落链路一条独立节流通道，不再与 `logDrive` 抢那一个名额）。

## 定位与改法

### 1. 挖矿：卡住判据必须覆盖**每一条**走位路径（本轮修的）

九百三十 的日志（12:30 段，节选）：

```
12:30:07  work exit: maid=… reason=mine 朝挡路块推进(够不着矿) blocker=(-1399,6,-680) …  feet=(-1398,2,-675)
12:30:12  work exit: … reason=mine 朝挡路块推进(够不着矿) blocker=(-1399,6,-680) …
12:30:17  work exit: … reason=mine 朝挡路块推进(够不着矿) blocker=(-1399,6,-680) …
12:30:22  work exit: … reason=mine 朝挡路块推进(够不着矿) blocker=(-1399,6,-680) …
12:30:23  mine give-up: maid=… reason=超时够不着 target=(-1399,8,-680) dist=… feet=(-1399,2,-677) progress=0.0
（12:30:28 玩家收放，id 8 → 1929；随后她立刻挖掉脚边 y=1 的 deepslate_iron_ore）
```

读法：目标矿在 `(-1399,8,-680)`，**比她的脚（y=2）高约 6 格**；中间那块够不着的挡路块在 `(-1399,6,-680)`。整整 16 秒里她**每一拍都走"朝挡路块推进"这一条**，脚下高度**始终 y=2**（`(-1398,2,-675)` → `(-1399,2,-677)` 只有水平微动），`progress=0.0`。

真身：`MaidMineBehavior` 里那段

```java
if (blocker != null && blocker.openable()) {
    if (bDistSq <= reachSq()) { …切目标为挡路块… }
    else { walkToBlockFace(blocker.pos()); return; }   // ← 这条 return 在 wedge 之前
}
```

—— **"够不着矿"那条分支有 2 秒卡住判据（wedge），"够不着挡路块 → 走过去"这条分支完全没有**：她顶在洞里爬不上去（挡路块在她上方 4 格、`walkToBlockFace` 只会在**同一层**朝挡路块脚下走，不会搭高、也不会挖），只能一路等"够不着超时"，玩家看到的就是"站着不动"。

**改法（两树）**：把 wedge 逻辑**抽成共用帮手** `wedgeAbandon(level, maid, anchor, gameTime)`（判据 = 脚下格整整 `MINE_WEDGE_TICKS`（2 秒）没动），**两条路径都调它**：

- 矿路分支（原来就有的那段）改为一行 `wedgeAbandon(...)` 守卫（行为逐字等价；"连着 3 次弃置 → 换框"的 `wedgeStreak` 逻辑随之内聚到帮手、两块共用）；
- 挡路块分支**新增**：先 `wedgeAbandon(...)`（卡住就弃、下一拍换目标）；再补一条**搭高抬升**尝试——挡路块在她上方且够不着时调 `pillarUpStep`（与 `approachOre` 的 `dy>=1` 同一条能力；放不上去/没料返回 false，自然落到下面的走位兜底），成功则抬升后朝挡路块推进。

于是"矿在头顶几格、中间一块石头够不着、她在洞里爬不上去"这一类，**要么 2 秒内换目标、要么先把脚下垫高**，不再原地等 16 秒。

### 2. 固定翼降落：加一条**独立**日志通道（本轮插桩）

九百二十九 把降落日志接进了 `logDrive`——而 `logDrive` 是**每坐骑 5 秒一个名额**的节流，降落链路有十来条日志抢那一个名额，`定跑道` 这行基本上永远排不上；实测每 5 秒只有一行降落日志，**"这条跑道到底规划出来没有"看不见**。

**改法（两树）**：新增 `logLand(mount, kind, detail)`——限频键是 **`坐骑 UUID + 日志种类`**，间隔 **1 秒**（`LAND_AT` + `LAND_LOG_INTERVAL_MS = 1000L`），前缀统一是 `固定翼降落·<kind>`。降落链路 9 处既有输出（完成 / 电量见底 / 进场（why）/ 接地段（why）/ 进近（why）/ 进圈（why）/ 盘旋（why）/ **定跑道**）全部改走它，另**新增 5 处**此前完全静默的转折：

| 新增日志 | 说明 |
|---|---|
| `规划退避（1 秒内不重扫）` | 挑不出跑道时那段 20 拍退避，不再静默（原本每拍重扫 625 列却一行不说） |
| `跑道作废（漂出钉住窗口）` | 漂出 `AIRCRAFT_LAND_PLAN_KEEP_D` 才作废——九百二十九 的病就是它被反复踩爆 |
| `规划失败（主人那一侧 / 以她自己为圆心都挑不出跑道）` | 两侧都挑不出条带 |
| `拉黑跑道（两分钟进不了场）` | `aircraftLandReject` 的拉黑，原本静默 |
| `作废（这一拍不再走降落档）` | 过渡那一次丢掉跑道规划缓存 |

**只加日志，不改任何降落判据、常量、控制流。**

- 状态：**未验收**（已部署：本机 4 实例与 `patched/` 逐字节一致；未回归、未 commit、未 push）。
- **挖矿怎么看**：让她去挖矿（尤其"矿在头顶、中间隔石头"的地形），在 `logs/latest.log` 里搜 `mine give-up:` 与 `work exit:`——这一轮之后同一种卡法应表现为：
  1. 反复出现 `reason=mine 朝挡路块推进(够不着矿)` 且 `feet` 高度**不变** → 现在最多 **2 秒**就会转成一行 `mine give-up: reason=2秒没挪窝`，下一拍换目标（不再等 16 秒）。
  2. 看到 `work exit: … reason=mine 朝挡路块搭高` → 挡路块在她上方够不着，她在**垫方块抬升**（这是正常动作，不是故障）。
  3. 连着看到 3 次 `give-up: reason=2秒没挪窝` → 会跟一行 `mine box unreachable (3 连弃置、零破坏) → fresh box`（换框）。
- **降落怎么看**：让她坐固定翼点 home（或"机上有人且周围无敌人"），日志里 `固定翼降落·` 开头的行现在**每种每秒最多一行**，可逐层读：
  1. 有 `固定翼降落·定跑道 … 距主人=N格` → 跑道**规划出来了**（这是九百二十九 看不见的那一行）。
  2. 反复 `固定翼降落·规划失败（…都挑不出跑道）` + `规划退避` → 这一带**没有可用条带**（地形太碎/太陡/水面）。
  3. 反复 `固定翼降落·进场 … 距接地点=… 横向=… 航向误差=…` 且"距接地点"一路增大 → 她**没对准**、在沿跑道轴飞出去重建距离。
  4. `固定翼降落·拉黑跑道（两分钟进不了场）` → 这条跑道被连续 2 分钟进不了场而拉黑，下一拍改选别的方向。
  5. `固定翼降落·进圈 … 距主人=N格` → 她不在以主人为圆心的跑道圈内，正在先飞进圈。
  - 请把降落那一段（含时间戳）整段贴回来——**这一轮之后每种转折都有自己的一行**，不用再猜。
