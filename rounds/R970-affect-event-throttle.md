## 需求 / 来源
- 开发者：「由代码触发的这些情绪效果要有最小间隔，30秒计一次，防止被高频伤扣死。」「非玩家的那些伤害只能影响心情，但是不影响亲密。」
- 开发者（提问）：「除了代码调控。大语言模型自己参与这些情绪的判定和数值调控吗？」

## 改法
1. **30 秒最小间隔（`AffectManager`，两树）**：新增 `MIN_EVENT_INTERVAL_MS = 30 * 1000L` 与"每女仆 UUID → 8 个时间戳"的内存表（`ConcurrentHashMap`，只存内存、重启清零、无副作用），以及 `allow(maid, kind)` 判定：距上次同类事件不足 30 秒 → **整次丢弃（一个数值都不改）**；够 → 记下此刻并放行。八类事件各自独立计时（挨打与喂食互不挤占）：
   `K_HURT_OWNER / K_HURT_STRANGER / K_HURT_WORLD / K_FEED / K_PRAISE / K_MESSAGE / K_APOLOGY / K_QUESTION`。
   受影响的写入点：`onOwnerMessage`、`onOwnerFeed`、`onOwnerPraise`、`onOwnerApology`、`onOwnerQuestion`、`onHurtByOwner`、`onHurtByStranger`、`onHurtByWorld`（`tickRecover` 不变——它本来就有"距上次受伤 ≥10 分钟"的独立闸）。
2. **判定边界写进类注释**（同时是核对结论）：
   - **非玩家来源的伤害只动"情绪面"**（愉悦 / 支配 / 冲突 / 受伤债），**一行都不碰亲密**；亲密只由"主人的行为"（对话 / 喂食 / 夸奖 / 道歉 / 主人打）与时间推移决定（核对：`intimacy` 的全部写入点共 5 处，四条非玩家路径 0 处）。
   - **大语言模型只读不写**：模型经 `ai_affect` 注入读到情绪快照来定语气；数值判定与修改**全部由代码规则**完成（游戏事件 + 主人消息关键词匹配），模型既没有写接口（无对应 AI 工具），它的输出也不会被解析成情绪事件。

## 模型是否参与吗？（本轮核对结论，供后续设计参考）
- **写**：只有 `AffectEventHooks`（`LivingHurtEvent` / 右键交互 / 每 20 秒 tick）与 `ReplyFeedbackTracker`（对**主人**消息做关键词匹配：道歉 / 夸奖 / 提问）调用写入方法。**没有任何 AI 工具**（`com/maidsmart/tool/*` 与 `memory/RememberTool` 等）碰情绪数值；`remember` 工具只能写**记忆**（含 `emotion` 标签的段落），记忆不回写情绪数值（只是下一次作为上下文再被模型读到）。
- **读**：`ai_affect` 上下文（`ProMaidExtension` 注册）→ `render()` 文本；`AffectSnapshot`（记忆快照的 `{"affect":{...}}` 字段）、每日关心点（`CarePointGenerator`，纯规则）、手册/状态面板（`BlueprintBookNetworking` 的状态行）也都是读。
- **结论**：模型是"读者 + 表达者"，不是"裁判"——它决定**怎么说**，不决定**数值是多少**。如果以后想让模型参与判定（例如由它判断主人那句话是不是真心道歉），需要新开一条"模型输出 → 结构化解码 → 限幅写入"的通路，本轮没做。

## 边界
- **30 秒是"每类事件"的窗口**，不是全局：挨打与喂食互不挤占；同一类里"最后 30 秒只算一次"，更频繁的触发**被整次丢弃**（不是折算成小值）。
- **计时表只在内存**：服务端重启即清零（情绪数值本身照旧落盘）——重启后第一次事件必然计一次，属预期。
- **`tickRecover` 不受 30 秒闸管**：它是"安静 10 分钟"的慢恢复，与突发事件的限频是两套口径。
- **世界伤害仍会造成受伤债**（只是不碰亲密、且 30 秒一档）——受伤债因此不再被"每拍伤害"瞬间顶满。
