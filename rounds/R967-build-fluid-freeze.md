## 需求 / 来源
- 开发者：「建造状态下的一个老门禁也要回来了：建造状态女仆所搭建的方块为静止状态。就像水是静止的。沙子会悬空这样。反正最后蓝图会统一替换。加了这样的门禁可以大大加快搭建的速度。」
- 其中「最后蓝图会统一替换」= 实测九百六十一 的**完工整体重放**（静默清空 + 按蓝图整片重放，终态 = 图纸本身）——这正是"建造期允许方块静止"的前提。

## 评估
- **现状**：建造区保护这一族已有四档（随机刻冻结 / 下落方块重力冻结 / 蓝图树叶不衰减 / TNT 点火压制），全部由 `build.areaProtection`（默认开）统一管。**流体这一档缺失**：R950 查明了"液体一落位就会自己排上流体 tick 开始流动（`onPlace` 无条件被调，与 flag 无关）"，但当时只能用**顺序规避**（把液体挪到计划末尾放、机器蓝图里插在动力源之前）。
- **代价（用户看到的现象）**：围壁还没砌完，水先漫出去——冲散随后放下的红石粉 / 火把 / 铁轨、漫过没建好的槽；缺口扫描发现洞又回头补，来回好几轮。重力方块其实已被重力冻结保住（不会掉），**唯独流体没有**。
- **用户要的正是"时间静止"的那一档**：搭建中的方块（含流体）静态 → 少一大类返工 → 更快；终态交给完工整体重放统一抹平。
- **级别**：P2（建造效率 / 返工量；不动判定、不动数据）。
- **风险**：低-中。唯一要小心的是**别把流体的"下一次 tick"弄丢**：流体 tick 是自续的（调度 → 流动 → **再调度**），单纯 cancel 会让这一格从此永远没有下一次 tick——完工解冻后水 / 岩浆也不再流（刷石机不结石头、水道不动）。所以本轮做成**重排 + cancel**（暂缓：冻结期每 5 拍回来问一次），区域一解冻就按原版物理继续。
- **完工链路已核对**（顺序即安全边界）：`activateWater`（水，flag 3）→ `settleTntIgnition` → `cleanupDrops` → **`BuildPlan.clear`**；重排出去的 tick 延迟 5 拍，全部落在 `clear` 之后触发 → 解冻即恢复。这条**不依赖** `snapFinish` 是否开启（超大蓝图跳过重放时同样成立）。

## 改法
1. **两树新增 `mixin/FluidFreezeMixin`**：`@Mixin(FlowingFluid.class)`，`@Inject(method = "m_6292_" / "tick", at = HEAD, cancellable)`：开关关 → 返回（回原版）；位置不在建造区 → 返回；否则 `level.scheduleTick(pos, state.getType(), 5)` + `ci.cancel()`。两条理由写进类注释：①流体一落位就流（R950 既有结论）；②必须"重排"而不是"丢弃"（上面风险那一段）。
2. **注册**：两树 `mixins.promaid.json` 各 +1 行（与 `GravityFreezeMixin` 相邻）。
3. **开关口径**：沿用既有 `build.areaProtection`（默认开、随 DIY 关）——配置注释在"重力冻结"之后补「流体静止（水/岩浆不流动、不外溢）」，关闭说明补"水会漫流"；4 个语言值（两树 × zh/en）同步；`ARCHITECTURE-SWITCHES.md` 重生成。
4. **架构数据**：新文件登记进 `promaid.work.build-plan` 模块 source（它正是 `BuildPlan.isBuildingRegion` 的归属模块），重跑 `tools/arch/build_arch.py`。
