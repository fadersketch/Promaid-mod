# R950 建造顺序：水和岩浆改到最后放（刷铁机 / 刷石机的水不再中途漫流）

> 跑道：承接 `rounds/R949-*.md`（多人「配置以服务端为准」+ 部署）。本轮来源是**开发者实测反馈**：
> 建筑功能有 bug，刷铁机和刷石机的**水会异常**，可以最后加水和岩浆。

## 排班

## 症状 / 现场

刷铁机（村民机）与刷石机这类**靠水/岩浆工作**的机器，女仆建好之后水不对：水道不成形、水漫到不该到的地方，
机器看着建起来了却不干活。

## 根因（一条：液体放得太早）

液体块一落位就自己排上流体 tick 开始流动（**与 setBlock 的 flag 无关**，onPlace 无条件被调，见
`MaidBuildBehavior` 里既有的字节码结论）。而水/岩浆在**两套搭建顺序里都排在很前面**：

- **通用顺序**（`BlueprintStepMath.centerSteps`：结构 → 家具 → 装饰/红石 → TNT，键 = buildPriority → y → x → z）：
  `LiquidBlock` 不在任何名单里 → 落到 **prio 0 = "结构主体"**，和墙、地板一起最先建。
- **机器专属顺序**（`BlueprintMachineFinish.machinePhase`：结构 1 → 惰性机构 2 → 活动件 3 → 传感 4 → 动力源 5 → TNT 6）：
  `LiquidBlock` 被归进 **相位 2** 的惰性机构组 → 也在结构刚起来时就放。

于是围壁（水道两侧的方块、刷石机的槽壁）还没建起来，水先流出去：推人水道被冲散、水流漫过没砌好的槽；
流到还是空气的干燥区，还会**冲掉随后放下的红石粉 / 火把 / 铁轨 / 作物**（流水会冲掉落这些方块）。
机器"建好了"却不工作——正是开发者看到的现象。

## 改法（三处，两树镜像）

1. **通用顺序：液体整段挪到计划末尾**（新方法 `BlueprintStepMath.moveFluidsLast`，稳定分割：非液体保序在前、
   液体保序在后，两者内部次序都不动）。挂在 `BlueprintLib.centerSteps` 出口上——建造创建、续建、投影、索引石、
   LLM 建造工具四条路径共用它，一处生效全部生效。无液体的蓝图先做一次字符串预筛，直接跳过整趟解析。
2. **机器专属顺序：液体插在【动力源之前】**。机器是**活放置**（flag 3），动力源一落下机器立刻运行，
   所以液体不能排到动力源之后（否则机器先空转、活塞头占住水道格）。做法是把 `LiquidBlock` 从相位 2 移出、
   自成一相 **5**，动力源 5→**6**、TNT 6→**7**，同步把"同相内红石线先于红石块/火把/拉杆"的特例判据改成 `pha == 6`。
   这样：结构 → 机构 → 活动件 → 传感 → **液体** → 动力源 → TNT，机器一通电就是完整状态。
3. **配套一道延后闸**（`MaidBuildBehavior` 的延后轮询）：液体排到最后之后，**支撑格是蓝图里液体步骤**的附着块
   （睡莲这类）必然先于液体被扫到，会被反复判"悬空放不上"。既有的"等蓝图支撑"分支有 10 次上限，大型蓝图里
   会在水放下来之前就把它跳过——现在这一种（支撑格命中 `isFluidStepAt`）**不计数、等到底**。

## 边界（没动什么 / 已知取舍）

- **液体的相对次序保持不变**：只做"整段后移"，水与岩浆之间、以及它们各自的先后照蓝图原序，不重排。
- **`activateWater` 仍是唯一的水流激活动作**：完工时把水源块整体重放一次（flag 3）→ 流动、气泡柱成形；
  液体放到最后反而让这一步更可靠（源块齐了再一起激活）。
- **机器蓝图的液体排在动力源之前**（不是绝对最后）——这是刻意的：机器是活放置，动力源落位即开跑，
  液体必须在那之前就位。无动力源的机器与普通建筑里，液体就是最后一件事。
- **续建/换朝向**：计划次序由蓝图现算，旧存档里正在半途的建造会按新次序继续（已建格由已建感知跳过，进度不白费；
  与 v1.5.316 上机器顺序那次的取舍一致）。
- **不含液体的蓝图零影响**。
