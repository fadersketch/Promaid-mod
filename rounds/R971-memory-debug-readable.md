## 需求 / 来源
- 开发者：「还有一个问题就是链路调试界面下面那些条目显示不全，只能看见前几个字。对了，女仆记忆中，女仆写的日记也显示不全。有一部分玩家希望女仆的记忆是可视化的」
- 附带截图：链路调试页底部条目形如 `[关系 置信度0.8] 主人night_rest主人答应今晚先好好...`——只有前半截。

## 改法
1. **`wrapLines()`（`BlueprintBookScreen`，两树）**：把逻辑行按 `font.width()` 折成"视觉行"——渲染与分页**共用同一份结果**（页码因此与实际可见行严格一致）。折行时记住行首连续颜色码（`§d§l…`），续行自动补回，不会掉色；切点若落在 `§` 码中间会回退一位，不劈开颜色码。
2. **记忆页（女仆记忆 tab）**：渲染（`renderMemoryView` 的记忆分支）与翻页按钮（`memoryViewButtons`）都改成"先折行再分页"，行高统一 `TEXT_LINE_H = 11`。**顺带修掉一个既有不一致**：翻页用 `/10`、渲染用 `/12`，两边的"每页行数"本来就不是同一个数，页数与可见行对不上 → 末页会被切掉一行。
3. **链路调试页**：
   - 行按钮：`fitText(line, 200)` → `fitText(line, btnW - 30)`（按按钮真实宽度截断）；高度 14 → `DEBUG_ROW_H = 20`（原版按钮贴图是 20px，14px 会把贴图压出横缝），行距 15 → 21。
   - 状态区：新增 `debugStatusSource()` 作为**唯一**内容源（`debugStatusLines` + 选中行的全文段），渲染与状态区分页按钮都走它；文本先按窗口宽折行再按 `maxStatus` 分页；行高 11。
   - **选中行全文**：点中某条记忆行时，状态区末尾追加两行——`§e▷ 选中行全文§7（<重要度/访问/tags 或 置信度>）：` 与 `§f<完整内容>`；再点一次取消选中。长段落因此不必靠猜。
   - 行区容量：两处 `rowsTop` 由"状态**容量** × 12"改为"状态**实际显示行数**（折行后）× 11"，`maxRows` 除数 15 → 21。
4. **服务端放宽截断（`BlueprintBookNetworking`，两树）**：`collectDebugStatus` 里记忆日记 `clip(r.content(), 70)` → **400**、工作笔记 `clip(note, 80)` → **320**——服务端不再替玩家决定"只看前面一截"，长度上限仍留（防一条记录把包撑爆），完整显示交给客户端折行 + 分页。

## 边界
- **折行是"显示层"的事**：不改服务端下发的数据结构（仍是 `List<String>`），也不改记忆文件的任何内容；只有长度上限从 70/80 放宽到 400/320（超长单条仍会被 `clip` 收口，避免一条记录撑爆网络包）。
- **行高 11 是折行后的行距**（原 12 略挤、10 太密）：一屏能多显示一两行；`DEBUG_ROW_H = 20` 只影响链路调试页的行按钮（对齐原版贴图），不影响其它面板。
- **"选中行全文"只显示一行内容**：`collectDebugRows` 的 `r[3]` 本身就是这条记忆的完整文本（服务端从未截断行数据），本轮只是把它在界面上**展开**；关系行显示的是 `主体+谓词+客体`。
- **"记忆可视化"（时间轴 / 关系图 / 重要度直方图这类真·图形化）本轮没做**——它是独立的一档功能（要新面板 + 新交互），等开发者点头再排。
