## 需求 / 来源

- 现象①「卓越前线载具还是做不到正常降落，仍然是飞走、一去不复返」——**降落本身是成功的**（下面有 03:20:55「已接地」的铁证），坏的是**第二次进场**：她已经在接地点上、机头朝反，代码却没有「先把姿态摆正」这一段，于是每条跑道都在 5 秒后被拉黑，最后一条都不剩 → 交回巡航档飞去主人那边。
- 现象②「女仆垫了几个方块，然后就站在原地不动了……某个链路走到中途，被放弃掉了，但是又没有找到下一个目标」——**框空迁移在「主人就贴着她」时算成 (0,0) 原地不动**：同一片空框被无限重扫，看门狗每 8 秒重置一次也没用（它清完锚点又埋回她脚下，还是那片空框）。

## 定位与改法

### ① 固定翼降落：日志铁证 + 与参考实现的差别

**日志**（`1.21.1-NeoForge/logs/promaid.log`，同一次实机）：

```
03:20:55 [模组坐骑] 卓越前线载具(AIRCRAFT) 固定翼降落完成：已接地 → 停住不动（home 模式）   ← 降落本身是成功的
03:21:11..03:21:36 固定翼起飞被拦：周围没有落差足够小的助跑地（环境不允许起飞）  ×6            ← 换她找起飞带（另案，未动）
03:22:06 [模组坐骑] 固定翼降落·复飞（home 模式）近端没对准 → 拉起重选 横向=0格 航向误差=168度 距接地点=0格
03:22:11 同上 航向误差=158度 距接地点=0格                                                   ← 与上一条【恰好 5 秒】
03:22:16 同上 航向误差=158度 距接地点=0格
03:22:21 固定翼巡航档 … 距目标=1009格                                                      ← 三次复飞之后交回巡航
03:22:26 / 31 / 37 距目标=804 / 454 / 110 格                                               ← 一路朝主人飞（"一去不复返"）
```

**定位**（`MaidMountCompat`，两树）：

1. **没有「进场段」**。旧口径只有两段：`if (before < ALIGN_D×ALIGN_FRAC && (横向出走廊 || 航向差过大)) → 复飞`，否则追中线前方一点往下走下滑道。她当时**就在接地点上**（`距接地点=0格`）、机头朝反（168 度）——纯追踪瞄准点在那种位置是退化的（`aimS` 被写成 0，等于瞄她自己脚下），既不会把她带出去重建距离，也不会在低空歪着的时候拦住她。对比参考实现：它有**完整进场**这一段——`RunwayApproach.follow` 用 Dubins 路径（转弯半径 `max(65, turnRadius×1.1)`）把她送到**跑道轴线上 160~200 格处的入口**（`entryDistance = max(160, min(200, turnRadius×1.5))`），高度不够就**多绕几圈盘旋降高**（`circles` 由高度差 ÷ 每圈降幅算出来），只有当 `along>65 && 横向<max(10,span×0.7) && 航向差<15° && 高度贴着下滑道 ±14` 时才算「建立」，才切进 APPROACH。**我们缺的就是这一段**。
2. **复飞 = 拉黑 + 作废规划**（`aircraftLandReject` → `AIRCRAFT_LAND_PLAN.remove`），而跑道规划缓存只有 `AIRCRAFT_LAND_RETRY_TICKS = 100L` 拍（5 秒）→ 每次过期都**绕着她当前位置重挑**候选点与八个方向。她没动、机头还是反的，于是新挑的那条也立刻复飞——**三条候选点（`AIRCRAFT_LAND_TRY=3`）用完 ⇒ `aircraftLandPlan` 返回 null**。
3. **汤姆6 的 null 分支是 `return false`**（交回巡航档），于是她掉头飞向主人（`距目标=1009格` 那一串）——**这正是"飞走、一去不复返"**。

**改法**（两树，同一份逻辑）：

- **新增「进场段」**（`aircraftLandFinal` 开头）：先把判据从"近端"改成**全局**——`|横向| > 走廊(14) || |航向差| > 上限(40°) || 高于 pattern 高度 + 容差` 三个条件任一成立，就**先不往下降着冲**：
  - **还太高**（高于 `接地点 + AIRCRAFT_LAND_PATTERN_ALT(24) + TOL(10)`，从巡航高度被点 home 就是这一档）→ **绕圈降高度**（复用等待盘旋的控制律，降率 0.2 格/拍）。直线往里飞会"冲过接地点还在往下掉"：0.2 格/拍的降率追不上 3 格/拍的航程（参考实现也是盘旋降高，只是它算的是"绕几圈"）。
  - **太近 / 已过站 / 机头朝反**（`|航向差| > 90°` 或 `距接地点 < AIRCRAFT_LAND_OUT_D(90)`）→ 瞄**跑道轴线上"她前方 OUT_LEG(90) 格"的中线点**：这是**跟踪式**瞄准点（她越往外它越往外），飞过它也不会掉头来回拉锯，等于"沿轴线飞出去重建距离"。
  - **还在进近区、机头也朝这边** → 追中线前方一点（前视距离随横向偏离放大到 80 格 = 最大约 45° 拦截角），一边靠中线一边往里飞。
  - 这一段**高度钉在 `接地点 + 24` 格**（地形净空线兜底）、**保巡航推力**（固定翼升力 ∝ 速度，收了油门既没升力也没舵效）；**只有对准了（横向进走廊 + 航向差 ≤40°）且降到 pattern 高度**，才走下面原有的下滑道/接地段。
- **复飞不再是"拉黑 + 换跑道"**：旧的那整段删掉（低空歪着撞地在结构上已经不可能——没对准就不下降）。黑名单只留给一种情况：**一条进近航道连续 2 分钟都没能进场**（`AIRCRAFT_LAND_PATTERN_LIMIT = 2400L`，够不着/一直太高，多半是山壁或水面挡死）→ 才拉黑换一条，同时打一行不节流的留痕「固定翼降落·换跑道」。
- **一场降落钉同一条跑道**：`AIRCRAFT_LAND_PLAN` 的缓存有效期从 100 拍（5 秒）改成 `AIRCRAFT_LAND_PLAN_KEEP_TICKS = 6000L`（5 分钟），外加一道**漂移作废**——她离那张规划里的接地点超过 `AIRCRAFT_LAND_PLAN_KEEP_D = 200` 格就重新规划（否则她已被带走很远时会掉头飞几百格去落旧跑道）。旧版"5 秒换一条"正是三次复飞恰好间隔 5 秒的原因。
- **没有可用跑道时原地盘旋**（汤姆6 那条 `return false`）：新增 `holdAircraftPattern` —— 以「她当前位置往侧向 60 格」为圆心追**切向瞄准点**绕圈（起步就与机头相切、不会有折角），高度拉向给定目标（传她当前高度 = 原地等下一轮规划；传 `接地点 + 24` = 盘旋降高），盘旋方向按 UUID 定死免得来回翻。交回巡航档 = 她掉头飞去主人那边，这条改掉之后"规划不出来"只会让她在原处绕圈等。
- 顺带：进近段的下沉率上限从 `0.20` 提到巡航档那一档 `0.30`（0.20 撑不起 0.10 的下滑道——进近开头还挂着 3 格/拍的速度）；接地段仍是 0.10，最后贴地那一段照旧轻。
- **删掉的旧常量**：`AIRCRAFT_LAND_ALIGN_D` / `AIRCRAFT_LAND_ALIGN_FRAC`（近端复飞判据）、`AIRCRAFT_LAND_GOAROUND_LIFT`（拉起量，现由 pattern 高度接管）。

### ② 挖矿/伐木：日志铁证 + 根因

**日志**（`1.21.1-NeoForge/logs/latest.log`，同一次实机）：

```
03:23:48  mine behavior start（她刚被魂符重新召唤，id 72→840，落在矿脉旁）
03:23:49..03:24:09  连着 20 秒的 mine chain filled/burst（stone/dirt/coal/copper，16 块一条）   ← 一直在干活
03:24:09.288  mine chain burst (blocking): block=minecraft:stone broken=16                    ← 最后一条链路
03:24:20.135  mine stuck-reset: maid=840 idle=217t pos=(-1450,70,-670)                        ← 11 秒零动作后看门狗
03:24:36.132  mine stuck-reset: maid=840 idle=320t pos=(-1450,70,-670)                        ← 又一个 16 秒，位置一模一样
03:24:55      会话结束（她随后被再次收走）
```

**定位**（`MaidMineBehavior` / `MaidWoodBehavior`，两树）：框内矿挖空后走 `slideAnchor`（每 5 秒一个环宽）。它的方向是**朝主人**：`dirX = sign(主人x − 锚点x)`、`dirZ = sign(主人z − 锚点z)`——可这段代码里有一条"主人在身边 → 不迁移"的老口径：**当主人就在锚点上（水平 <1 格）时 `dirX = dirZ = 0`**，于是 `na` 与旧锚点**完全重合**（只清 `ORE_CACHE` 强制重扫同一片空框）。她就守在主人脚边挖矿，主人一动不动 ⇒ **框永远不动、永远空**；看门狗 8 秒一响，`hardResetStuck` 清掉锚点，下一拍 `relocate` 又把锚点埋回她脚下——还是那片空框。日志里"位置一模一样、每 8~16 秒重置一次"正是这个形状。

**改法**（两树，矿/木同口径）：

- `slideAnchor` 改成 **`boolean`**（真的滑走了才返回 true），并且**主人在锚点上时按 8 向轮转取方向**（`slideTurn` 每滑一次 +45°）：框绕着主人一格一格转着找，既不原地不动、也不会越挖越远（实测五百六十二 那条"home 不迁移"的原意保留——**home 限制圈内仍然不迁**，只是把"主人贴着她"这一支从"原地不动"改成"转着找"）。
- 滑走之后**留一行日志**（`mine relocate (box empty → fresh box)`），home 限制圈里空框也留一行（`mine box empty but home-restricted`），让下一次会话的日志能直接看出"框到底动没动"。
- **不加"朝新框赶路"**：这条老口径（实测九百一十三：框空不该赶路，走路交回原版 TLM）**保持不变**。理由：框动起来之后，全量扫描（`seekThroughWalls` 默认开）会在新框里挑出矿，`approachOre` 立刻接管走位/搭路——不需要、也不该再让她"先走过去再找"。
