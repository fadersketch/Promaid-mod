## 需求 / 来源

玩家反馈：两个版本在这类物品选择面板里都会出现文字超出屏幕；1.20.1（后两张截图）
还会有一条竖线挡住内容。

截图证据：

- 1.21.1 通用支援页：标题从屏幕中心开始向右冲出，底部图例同样被裁。
- 1.20.1 燃料页 / 超越维度页：底部说明行右侧被裁；下半屏有一条 192 灰的竖线，
  从输入框下方一直延伸到屏幕底，压住说明文字。

## 评估

### 一、文字越界（两树同因）

`drawCenteredLines` 名字是"居中"，实现却是：

```java
g.drawString(font, line, clampCenterX(line, width / 2), y, color, false);
```

`clampCenterX` 返回的是**圆心**，而 `drawString` 把 x 当**左起点**——于是每一行都从
屏幕中心开始向右画。单行时正好从 cx 冲到右缘；`wrapFit` 折出来的行也一样，所以
"折行"并没有解决问题。1.20.1 的燃料/规则页底部提示则用单行
`drawCenteredString(clampCenterX(...))`：文本比屏幕宽时 `clampCenterX` 的可行区间
倒挂，圆心被夹到 `8 + 半宽`，仍会冲出右缘。

修法：

- `drawCenteredLines` 改用真正的居中绘制（Forge `m_280653_` / Neo
  `drawCenteredString`），每行仍经 `clampCenterX` 钳制。
- 仍用单行绘制的长标题/长提示（通用支援标题、燃料标题与说明、烧制标题与说明、
  喂食/喂水标题与说明、超越维度标题与统计行、矿表提示）统一改为
  `drawCenteredLines(g, wrapFit(text), ...)`。
- 矿表两条提示合并成一个列表后按最后一行的位置向上排版，折行后互不重叠。

### 二、1.20.1 竖线（仅 Forge 树）

Forge 1.20.1 的 `AbstractSelectionList` 构造参数与字段（javap 实证）：

| 字段 | 含义 |
|---|---|
| `f_93388_` | width |
| `f_93389_` | height |
| `f_93390_` | **y0（视口上沿）** |
| `f_93391_` | y1（视口下沿） |
| `f_93392_` | x1（右缘） |
| `f_93393_` | x0（左缘） |
| `m_5759_()` | getRowWidth（默认 220） |

旧代码为了"行宽 = 列表宽"写了 `this.f_93390_ = width`——实际把**视口上沿**改成了
列表宽度（例如 391/540），而 `y1` 仍是 `top + height`（例如 178）。原版滚动条按
`fill(x1 - 6, y0, x1, y1)` 画，`y0 > y1` 被归一化成一条从列表下方一直伸到 y0 的
长竖条；它画在提示文字之后，于是正好"挡住"底部说明。8 个子页列表（矿表、木材、
替代品、喂食、喂水、支援、烧制、超越维度、搭方块禁用）全部中招。

同时旧代码的自绘滚动条坐标也全错：

```java
int sx = this.f_93389_ + this.m_5759_() - 6;   // height + rowWidth，不是 x
g.fill(sx, this.f_93392_, sx + 6, this.f_93393_, ...); // 用 x1/x0 当 y 坐标
```

它是逐条目调用的 `m_238964_`（renderEntry），每行重复画一次；原版滚动条随后又
画一遍。修法：

- 每个列表存 `private final int rowWidth`，构造时 `this.rowWidth = width`；
  `m_5759_()` 返回 `max(rowWidth, 120)`。不再碰 `f_93390_`。
- 删除这 8 个错误的 `m_238964_` 覆写，滚动条交还原版
  （`x1 - 6 .. x1`、`y0 .. y1`），子页列表的滚动条样式恢复为原版。
- 列表条目重新落在视口内，"移除/删除"按钮与行文本恢复可见（此前视口倒置，
  列表内容实际被裁掉，只剩那条竖线）。
