## 评估
- **现状清点**（改前）：这一页只有单向的批量配置——「✔ 一键全部加入」（实测八百二十八）：按**当前网格**（搜索框过滤后）批量设为可挖穿（内置软方块从排除名单移出 / 其余加进额外名单）。要反悔只有两条路：一个个点回去，或用「↩ 回退」退最多 3 步（实测八百二十九）。
- **口径决策**（本轮最要紧的一步，逐条说明理由）：
  1. **范围 = 障碍物两名单**（`extraBreakables` + `disabledBreakables`）。理由：「一键全部加入」就只动这两张（口径逐字一致的对偶），而且这两张是**挖矿 / 伐木两页共用**的——所以「挖矿和伐木」两处都自然生效。目标矿物 / 木材价值表与危险方块表**不动**：那两张没有「一键配置」键，不该被这个键牵连。
  2. **「全删」= 回出厂默认**，不是清空成空表。排除名单的出厂默认是内置自然软方块那一张（37 项）；清空它不是"删掉我配置的"，而是把状态改成"整片树林都能挖穿"。所以：额外名单清空（它的出厂默认本来就是空表）、排除名单整张恢复定义默认。
  3. **不看搜索框过滤**：加入是"先搜再一键加"（只处理筛出来的那批），删除是"整张复位"（对应"所有方块全部删掉"）。要挑着删就搜完再一个个点，或删完用回退。
  4. **可回退**：动作前拍 `MineSnap`（四张列表）→ `commitUndo`，所以「↩ 回退」一步整张还原；本键是回退机制的新用户，不是新机制。
  5. 名单本来就是出厂状态时**灰显**，点了给一行灰字提示（与「↩ 回退」同款，不静默失效）。
- **级别**：**P2**（子页易用性；误操作有回退兜底，不会造成不可逆损失）。
- **风险**：低——只加按键与一个动作，判定与数据结构都没动；出厂默认直接取 `MINE_DISABLED_BREAKABLES.getDefault()`，与 `defineList` 里那份默认同源，不会漂移。

## 改法
1. **加按键**（两树 `PromaidConfigScreen.mineTableButtons` 的障碍物分支）：「✔ 一键全部加入」右侧（`left + 168`，仍在那条空着的输入框行 `inputY`，宽 160）加「✖ 一键删除」；键面随状态上色——有得删 = 红（`§c`），出厂状态 = 灰（`§7`）。
2. **新增 `obstacleConfigDirty()`**：额外名单非空 **或** 排除名单 ≠ 定义默认 → 有得删（按键上色与空点提示都用它）。
3. **新增 `clearObstacles()`**：`listWriteBlocked()` 闸（服务端锁定且非 OP 时不可写）→ 出厂状态就灰字提示并返回 → 拍 `MineSnap` → 统计（额外名单删 N 项 / 排除名单复位 M 项）→ 两名单整张写回（空表 / 定义默认）→ `minableList.rebuild()` → 聊天栏汇总提示 → `commitUndo(before)` 落回退点。
4. **出厂默认的来源**：`MaidSmartConfig.MINE_DISABLED_BREAKABLES.getDefault()`。配置面**一字未改**（默认值仍内联在 `defineList` 里）；本轮一度把这份默认提升成 `DEFAULT_DISABLED_BREAKABLES` 常量，被 `check_panel_coverage` 判为"覆盖清单里的名字不是声明字段"（它的声明正则只认 `…… NAME;` 形状），遂改回 `getDefault()` 口径并把配置面复原（`git diff` 里这两个文件已无本轮改动）。
5. **注释同步**（同一页的三处）：回退块里"这页会批量改一大堆"的清单加上「一键删除」；`MineSnap` 的"哪个动作动了哪张表"说明补上它；按键处写清与「一键全部加入」的对偶关系与"不看过滤、整张复位"。
