1. 20:42:42 她收了铁锭，日志出现 `cook rebind: old (-164,-60,797) → next (-165,-60,797)`——
   玩家新放的高炉成为新绑定台。
2. 之后直到 20:43:15 退出，**没有任何** `cook round` / `cook scan` / `cook watchdog` / 气泡。
3. 存档实测：女仆 `(-162.5,-60,795.5)`、高炉 `(-165,-60,797)`，两者站位点相距约 2.3 格；

## 改动

### 1. 工作半径

- 炉子/烟熏炉/高炉：`standSq > 4.0` → `standSq > 9.0`（2 格 → 3 格）。
  原版炉子的成品/燃料操作不依赖精确站位，3 格完全够用；玩家在旧炉旁再放一台时不会再判"没到位"。

### 2. 站位超时兜底（`standStallTicks` / `standStalled`）

- 每 tick 走不到站位点累加，满 100 tick（5 秒）：
  - 离台 ≤5 格 → 标 `standStalled`，不再踢寻路，**就地开工**，日志
    `cook stand-stall: ... 5 秒走不到位（台=…，距 … 格）→ 就地开工`；
  - 离台 >5 格 → 解绑，炉子进 `STATION_STUCK_UNTIL` 10 分钟冷却（避免重扫又挑回同一台），
    日志 `... → 解绑重找`。
- 走到位、换台、绑定、营火迁移、行为重启时都清零 `standStallTicks` / `standStalled`。
- 营火分支（`distSq > 6.25`）加上同样的兜底：≤5 格就地烤，>5 格解绑。
- 结果：这条链路最坏 5 秒必有可见结果（日志 + 动作），不再存在"永久静默返回"。

### 3. 拾取扩到周身 5×5

- 新增 `sweepCampfireDrops`：每 tick 在**女仆脚下方块 ±2**（5×5）内捡营火配方成品，
  接在 `sweepNearbyOutputs` 末尾（无论当前绑的是炉子还是营火都会跑）。
- `collectCampfireDrops` 的判定盒改为 `cookDropBox`：**营火自身 ±1.5 与女仆 ±2 的并集**——
  守在炉子边也能收回掉在营火附近的烤肉，贴在营火边也不会漏掉更远一点的掉落物。
- 捡取逻辑抽成 `collectDropsIn`（两树同名）：只收 `isCampfireResult` 的营火成品，
  背包 → 附属容器，两边都满就留在原地；成功时记一行 `Campfire / drop / 附近营火成品×N`。

## 边界

- 只捡**营火配方成品**（烤肉、烤土豆等），玩家丢在火边的杂物、原料不碰。
- 背包与附属容器都满时，掉落物留在原地，不会被吞掉。
- 炉子的"就地开工"只放宽到 3 格；更远时仍要求走到站位点，走不到就解绑换台。
- 站位超时只是兜底，不改变正常烧制节奏（正常 1~2 tick 内就到位）。

## 验收（两版本）

1. 女仆在熔炉前烧铁时，在她旁边 1~2 格放高炉：应在数秒内继续烧（日志出现
   `cook rebind`，必要时出现 `cook stand-stall ... 就地开工`），不再原地不动。
2. 营火烤好的肉弹到火外 2~3 格：女仆在附近（哪怕正守着炉子）应走过去/直接收进包，
   日志 `Campfire / drop / 附近营火成品×N`。
3. 背包与附属容器全满时，地上的烤肉应保持原样，不会消失。
4. 把女仆与工作台之间用方块完全堵死：5 秒后应解绑走开（日志 `→ 解绑重找`），不再永久站立。
