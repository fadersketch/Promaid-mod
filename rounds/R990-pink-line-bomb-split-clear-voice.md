## 改法

### ⑧ 聊天天线整行粉色（两树 `ChatBubbleLimitMixin`）

- R948 为逐段翻译把行拆成 4 个 Component（前缀 / 名字 / 尾巴 / `translatable(text)`），
  但颜色只写在第一个字面量的**内容**里（`"§d["`）——§ 码不跨组件边界，于是只有「[」被染粉。
- 现在每段各带 `ChatFormatting` 样式（forge `.m_130940_(col)` / neo `.withStyle(col)`）：
  `col = danger ? RED : LIGHT_PURPLE`；可见文本一字不变（普通 `[名字] 台词` / 敌袭
  `[警示][名字] 台词`），译文逐段路径不变（`PromaidI18n.tr` 各分支都保留 `c.getStyle()`）。

### ⑨ 三条链路分开（两树 `MaidBombing` / `BombTntTick` / `BombThrow`）

- `MaidBombing` 新增 `SETTLE_NEXT`（女仆 UUID → 可释放时刻）与 `SETTLE_PLACE_TICKS = 40`
  （放置类起手 +2 秒：起爆在 ~1 秒后，窗内谢绝其它链路）、`SETTLE_TNT_TICKS = 60`
  （TNT 离手 +3 秒：引信 2 秒 + 1 秒落停）；`forget` / `clearAll` 清表。
- `tryStartMelee` 起手循环加 `break`：**一拍只起一段**（就绪序 水晶 → 重生锚 → 床），
  起手即写静置窗；方法注释改口径（旧需求"两者可以同时启动"由本条取代）。
- `readyKinds` 顶部静置闸：窗内静默返回（不落"轰炸跳过"诊断）。
- `BombTntTick.flushTnt` 静置闸：窗内不追投（挂链最末的 TNT 因此与放置段错开）；
  `BombThrow.throwTntAt` 投出后写 `SETTLE_TNT`。
- 效果：水晶 → 重生锚 →（床）→ TNT 按 ~2 秒错开、每发都对着怪当下站的位置去；
  各段 10 秒最短间隔与压缩盒"一次最多 5 个"的连发口径不动。

### ⑩ 清敌语音两重确认（两树 `PerceptionManager`）

- 新增 `engageLast`（最近真在打的目标）+ `clearPending`（挂起表）+ `CLEAR_CONFIRM_TICKS = 40`
  + `CLEAR_PENDING_TIMEOUT = 200`。
- 目标丢失边沿：**只有最后一个目标已死**（`!isAlive`）才挂起；挂着时"重新接敌 → 撤销"、
  "`hostiles == 0` 且确认窗到点 → 播"、">10 秒等不到 → 静默放弃"。
- 语音文案、两条限频 key（enemy_near 300 秒 / enemy_clear 30 秒）与 `CLEAR_MIN_ENGAGE_TICKS`
  一字未动。

- ⑧ 聊天栏里她说的每一句（普通粉色 / 敌袭红色）**整行同色**，不再只有开头的「[」变色；

  怪被炸飞 / 钻地 / 目标记忆闪断不再触发；不再出现带 [警示] 前缀的"安全了"。

## 边界

- ⑧ 只改聊天栏镜像行的上色方式；气泡颜色、TTS、限频、翻译路径一字未动。
- ⑨ 静置窗只约束**跨链路**的释放时机：各段 10 秒最短间隔、TNT 引信 / 追踪 / 物理体积、
  压缩盒"同一次最多 5 个"的连发、空袭安全高度（先爬升再撒手）全按原口径；
  只开 TNT（放置类关）时行为与旧版逐项一致（10 秒间隔本就大于 3 秒静置）。
- ⑩ "附近"= 她 12 格内的威胁数（既有 `isThreat` 口径）；"清掉了"只报了结的**她自己**这一仗，
  不声称全地图安全；挂起超时（10 秒）后静默放弃，宁可不播也不误播。
- ⑧ 属**本版本尚未推送内容内的回归**（R948 引入、对已发布版本不可见），按《写作规则》
  不写进玩家文案；只记轮档与机制详解。⑨⑩ 改动的是已交付行为，写入玩家文案。
