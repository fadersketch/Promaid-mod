## 定位与改法（逐条，含日志铁证）

### ① 驾驶 Tom F6F 点 home → 不降落、直接飞走

**日志**（`1.21.1-NeoForge/logs/promaid.log`，02:15:39 起每 5 秒一条）：
```
[模组坐骑] 卓越前线载具(TOM6) 固定翼降落·复飞（home 模式）近端没对准 → 拉起重选 航向误差=106度 距接地点=3格
[模组坐骑] 卓越前线载具(TOM6) 固定翼降落·接地段（home 模式） 距接地点=0格 离地=79.78格 竖直速度=-0.10 水平速度=0.00
```
**定位**：`MaidMountCompat.aircraftLandFinal`（两树）**接地段只按"沿跑道方向进了 `TOUCH_D` 圈"切进去**（`if (before <= AIRCRAFT_LAND_TOUCH_D)`，不看高度）。她**离地 79 格**就被判进"接地段"→ 接地段把油门收到怠速、水平速度收到≈0；而固定翼的**升力/舵效 ∝ 速度**——速度没了，俯仰通道（`aircraftHoldAltitude`）就再也压不下去 → 吊在 79 格、竖直速度 -0.10、原地不动 → 玩家看到"飞出去/永不降落"。（同文件另一条退回口径 `flare = aboveGround <= AIRCRAFT_LAND_FLARE_ALT` 本来就是"又到点又到底"的写法，接地段缺了这条。）

**改法**：接地段加高度闸——`if (before <= AIRCRAFT_LAND_TOUCH_D && aboveRunway <= AIRCRAFT_LAND_FLARE_ALT)`。还高着就走下面的**进近段**（保巡航推力 → 沿下滑道继续降），到低空（≤6 格）才压平、收油、轻接地。

### ② 排班表「召她过来」/「一键集合」在 home 模式下点不动

**日志**（`latest.log`）：
```
[CHAT] 已开启「大正女仆狐酒」的在家模式——她将守家不跟随，想召回先关闭
[CHAT] 她在守家模式（排班中的 home）保持原位——想召回先解除她的排班/在家模式   ← 连点多次都是这句
```
**定位**：`MaidChunkLoadManager` 里"守家豁免"把**正骑在载具上**的她一起钉死了。开发者实机是"开着 home 点召唤"→ 被顶回、纹丝不动（两个按钮都落到这道闸）。另：`summonMaidTo`（服务「一键集合」）对"特殊载具 / 自坐模组载具"是**只传人、把载具丢在原处**——与开发者定的「一键集合 = 连人带载具一起」相悖。

**改法**：
- 守家豁免**不拦"她正骑/坐在载具上"**：`summonOne` / `summonNamed` / `summonMaidTo` / `summonAll` / `tickPending` / `queuePendingSummon` 的 `homeOnly/homeKept` 全部加 `!isPassenger()`（两树）。守家仍钉住**站在家里的她**；人一旦上了载具，手动点名就放行。
- 「一键集合」对"特殊载具 / 自坐模组载具"改走 `recallRideRider` 那条**"解乘客关系 → 搬载具 → 搬她 → 重新落座"**的连人带载具链路（与 716 档指挥棒坐骑同一段代码），不再"只传人、载具丢原地"。「召她过来」仍是"只拽人不拽载具"（`summonNamed` 不动）。

### ③ 自动复活倒计时永远刷回 5 秒、永远复活不了

**日志**（`promaid.log`，02:17:27 起每 5 秒一条，直到会话结束）：
```
[自动复活] 墓碑既不在实体表、也不在 TLM 登记表里（可能已被玩家取走/世界损坏）——本次跳过删除
[重同步] 大正女仆狐酒 补包跳过：她是新实体（收放魂符/重新召唤，id 5910→5911）   ← id 每 5 秒 +1
```
（对照：10-08 / 10-11 有成功线 `已在主人所在位置强制复活（新实体 id 2991 / 354）`；配置 `autoResurrectDelaySeconds=60` 也印证"第一次尝试在 +60 秒"，之后每 5 秒**都是失败重排**。）

**定位**：`MaidAutoResurrect.onServerTick`（两树）——`resurrect(...)` 返回 false 后 `p.dueTick = now + 100L`（**5 秒**），登记**永不摘掉**。而它反复返回 false 的原因是 `dest.addFreshEntity(maid)` 恒为 false（同 UUID 已存在：上一次其实已经把她放回世界、只是这条登记没摘掉/或被别的路径复活过）；HUD/排班表按 `ceil((dueTick-now)/20)` 就永远显示"剩 5 秒"。**这就是开发者看到的"倒计时结束又刷回 5 秒、反复刷新、永远无法复活"。**

**改法**（两树）：
- **根因**：`resurrect` 在 `addFreshEntity` 之前先按 UUID **全维度查重**——若同 UUID 的女仆**已经活着**在世上 = 这次本就是成功的，只补血/净化并**直接摘掉登记**（不再重复造人）。
- **兜底**：给失败重试**封顶** `MAX_RESURRECT_RETRIES = 12`（≈60 秒），到点放弃这条登记 + 如实播报"请右键墓碑取回物品"，彻底杜绝"永远 5 秒"。每次失败也留一行日志（第 N 次）。
- 注：`Pending.retries` **不落盘**（重启清零），与既有 `cleanupSince` 同性质，无 NBT 兼容负担。

### ④ 挖矿/伐木"没几秒就站着不动"（超时惩罚）

**日志**（`latest.log`）：
```
[com.maidsmart.task.MaidWorkBehavior] mine stuck-reset: maid=19 idle=189t pos=(-1475,73,-715)
[com.maidsmart.task.MaidWorkBehavior] mine stuck-reset: maid=19 idle=168t pos=(-1475,74,-716)
```
**定位**（`MaidMineBehavior` / `MaidWoodBehavior`，两树）：8 秒发呆看门狗 `stuckReset` 命中后，`hardResetStuck` 按 **R917 口径**把"锁着的那块 + 它的超时时钟"**原样保留**——可扫描分支只在 `targetPos == null` 时才跑，于是看门狗把同一块够不着的矿**反复重新锁上** → 永远进不去检索 → 她就一直杵着。另外 `stuckReset` 把"人不动 + 还没破块（`markProgress` 只在破块那一刻记）"误判成发呆，还顺手 `destroyProgress = 0` → 挖硬矿（深板岩钻石）**越重置越挖不完**。

**改法**（两树，挖矿/伐木同口径）：
- 看门狗**不再重锁原目标**：命中即 `this.targetPos = null` + 把这块记进 30 秒短排（`RECENT_DISCARD`）→ 下一 tick **从头重跑一次完整的目标检索链路**（正是开发者要的"重跑一次工作流程"），且不会立刻又选回同一块够不着的。
- 看门狗条件加一条：**`destroyProgress > 0`（正在破坏方块）也算"在干活"** → 不再把"正在挖硬矿"误判成发呆、也不再把破坏进度清零。
