## 需求 / 来源

开发者原话（与本轮第一件事同一条消息）：

> 为了避免issues37的问题，我觉得手册的内容必须要更加易读一点。同时不要提及过去。只提及当前情况下，这个物品这种情况该如何使用

转写成事实陈述：**游戏内手册（`GuideScreen` 那 35 章）的全部可见正文**要满足三条——

1. **不提过去**：不写"以前 / 原来 / 本来是 / 这一版 / 版本差异 / 改成 / 旧行为 / 按反馈加重了"这类对照叙事；
2. **只讲现在**：每句都在描述"当前版本此刻就是这样"；
3. **只讲怎么用**：主体是"这个物品 / 这个开关，这种情形下你要做什么"，不是"我们怎么实现的"。

对应台账 **TD-03**（"可见文档里的开发过程"）的**手册那一部分**存量清零；配置注释 / 面板工具提示那一大块
存量**本轮不做**（见 §边界）。

## 改法（定稿）

分**两批**做，都是"只动字符串、不动逻辑"。

**第一批——按编辑表逐条改写**（临时脚本把同一张 `旧串 → 新串` 表**同时**打到 10 个 java 正文与
2 个 `en_us.json` 的**键**上；键必须跟着中文串走，否则英文客户端会回落到中文）：

- **去对照叙事**：`六百四十五 起写死`→`写死`、`；方块形态留待以后。`→`。`、`第一版太淡、看不出是友方的东西，`→
  `颜色够重、一眼就能看出是友方的东西；`、`这一版按反馈加重了；`删、`版本差异只有一项`→`另有一条（本版特有）`、
  `原来她常驻在你身后`→`她常驻在你身后`、`六、本来要走过去的活，也交给飞`→`六、只能靠腿走过去的活，也交给飞`、
  `与同伴的间距原来不分场合`→`与同伴的间距要分场合`、`现在§r：门禁改成「她`→`门禁是§r：「她`、`仍走原来的投弹链路`→
  `仍走那条投弹链路`、`原来录的那条不会因为换了格式就丢`→`已录的那条不会因为换了格式就丢` …
- **去开发口气**：`时，我们§e把目标点`→`时，§e把目标点`、`，我们就托住她`→`，就托住她`、`我们一个数字都不改`→
  `本模组一个数字都不改`、`（与我们做仿创造飞行时定的口径一致）`→`与本模组的仿创造飞行口径一致`、
  `我们补一手强制放下`→`本模组补一手强制放下`、`我们只在她§e真的没活可干§r时`→`本模组只在她…`、
  `仍由我们带着闲逛`→`仍由本模组带着闲逛`、`我们的绳子不会断`→`本模组的绳子不会断`、`（附属源码如此）`→删 …
- **去行话**：`闸在正常`→`限制在正常`、`这道闸`→`这道限制`、`维度闸`→`维度限制`、`闸门`→`门禁/判定`、
  `判据`→`判定/口径`、`判据与女仆侧`→`判定口径与女仆侧` …
- **拆长句**：把"一段话里塞三四件事"的少数几条断成两条（如挖矿章"拿什么方块垫脚"）。

**第二批（收尾补齐，本轮最后一遍全量核对时发现第一批漏网的编码形态）**：
手册正文里混着**三种转义写法**（全字面 / 全 `\uXXXX` / 中文照写只有 `§` 转义），第一批的统计是按
*解码后*文本做的，落在**全 `\uXXXX`** 那批段落上的 `判据/闸门/我们/原来` 没被第一批的字符串匹配覆盖到。
收尾按"解码后正文"重新扫，把剩下的全部补掉：

- **中文**（java 正文 + `en_us.json` 的**键**同步改）：`判据`→`判定`、`闸门`→`判定`、
  `我们`→`本模组`（**对话引语除外**，见 §保留清单）、`原来那位一个字都不动`→`先前那位一个字都不动`、
  `全都是她原来那套`→`全都是她自己那套`。
  实现要点：对每条词生成三种转义形态逐个试；`我们` 那一条先用占位符把 4 句对话引语保护起来再替换；
  `en_us.json` 侧**只动"手册正文用得到的 key"**（762/765 条），不碰其它键，改完长度变了就用空格补齐原位写回。
- **英文 value**（键不动）：`criterion`→`rule`；`we only decide`→`this mod only decides`、
  `logic from us`→`logic of its own`、`We just pass the`→`This mod just passes the`、
  `we hand §eyou§r`→`this mod hands §eyou§r`、`something we push onto her…ourselves`→`…this mod pushes…itself`、
  `our rope never breaks`→`this mod's rope never breaks`、`still drawn by us`→`still drawn by this mod`、
  `gear we support`→`gear this mod supports`、`we hold her up`→`this mod holds her up`、
  `we only took the one thing`→`this mod only took the one thing`、`we don't touch navigation/any of it`→
  `this mod doesn't …`、`our creative-like flight`→`this mod's creative-like flight` …（共 45 处/树）
  同一段英文在文件里存在多种转义形态，逐形态都要替换。

## 保留清单（明确不动，免得过度改写）

- 玩法事实：任务名、按键、配置面板路径、配方、坐标/半径/数值、日志关键词、"关掉会怎样"的分支说明。
- 开发者的《寄语》章（`foreword`）：那是作者自述，本来就不是"物品用法"，保留其口吻。
- **玩家对女仆的原话**（引语）：`「上个月我们做了什么」`/`「记下我们在挖钻石」`/`「你还记得上次我们…吗」`/
  `「上周/这个月我们都做了什么」` —— 这是**你要说的话**，`我们` 就是对的，**保留**（英文同样保留 `we`）。
- 正常用法的"改成 / 之前 / 以前"：`把「投喂触发饱食度」改成 20`（教你怎么调配置）、
  `优先级在治疗之前`、`写推力之前先问一遍引擎的电量闸`、`你以前跟它交过手`（描述游戏条件）——都不是在讲版本历史，**保留**。
- 两树的**版本差异段**（1.20.1 与 1.21.1 本来就不一样，例如 Neo 树有"重锤猛击"章、Forge 树标"1.20.1 只有这两路"）：
  按同口径改写，但**不强行拉平**——那三段文件两树本来就不逐字节相同（`GuideChaptersBasics/Combat/Flight`），
  只有 `GuideChaptersSystem/Work` 是逐字节相同、改完仍逐字节相同。
