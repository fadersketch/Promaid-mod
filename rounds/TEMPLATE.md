> 复制本文件为 `rounds/RNNN-slug.md`（NNN = 与 `CHANGELOG.md` 里 `## 实测NNN` 一致）。
> 流程见 `WORKFLOW.md`；格式只为让人（和下一轮的自己）能接手，不求长。

## 排班（开工前先填，硬门禁 —— `WORKFLOW.md` §1）
- **跑道**：A 修 bug / B 新功能 / 只改文档；一句话判定依据。
- **开工前读过**：`ARCHITECTURE-SWITCHES.md` 的哪一节 / `BUG_DEBT.md` / `TECH_DEBT.md` / `rounds/RELEASES.tsv` / 上一轮记录 —— 结论（已有等价开关？已记的债？）。
- **工作队列**（逐步，做完就勾；每步写"完成判据"）：

| # | 步 | 完成判据 | 状态 |
|---|---|---|---|
| 0 | 例：定位（找日志/补诊断） | 拿到能指向代码的那一行留痕 | ☐ |
| 1 | 例：根因 + 同类点 | 根因指着证据说；grep 清单逐条处置 | ☐ |
| 2 | 例：两树改 + 编译 | `EXITCODE=0` | ☐ |
| 3 | 例：打包装机 | 4 个目标与 `patched/` 同字节 | ☐ |
| 4 | 例：交开发者验收 | 开发者实测后给出结论 | ☐ |

- **谁验收 / 怎么验**：验收人 = 开发者；验法 = 按下面的复现步骤实测 + 看 `logs/promaid.log` 哪几个关键词。

## 需求 / 来源
- 谁提的 / 哪来的：issue #编号 / 实机反馈 / 台账里的 BD-xx · TD-xx / 自己的规划。
- 一句话需求（转写成事实陈述，不抄原话）。

## 评估
- **跑道**：A 修 bug / B 新功能（判定依据一句）。
- 走 A 时：级别（P0–P3）+ 证据（崩溃栈 / 日志行 / 命令输出）+ **根因三问**（复现 / 根因 / 同类点清单与处置）。
- 走 B 时：**前置四问**答案（① 重复性 ② 语义：纯新增还是改既有行为 ③ 耦合：开关入口与优先级 ④ 性能：频率/范围/最坏开销/开关）。
- 先查过 `ARCHITECTURE-SWITCHES.md`（已有等价开关？）与 `BUG_DEBT.md` / `TECH_DEBT.md`（是不是已记的债？）：结论写这里。

## 改法
- 关键改动逐条；被否掉的方案与原因（省得下一轮再绕一圈）。

## 触及文件
- 两树各哪些文件；新配置项 / 新 i18n key / 新 mixin 各几个。

## 验证
- 命令 + 结果（`javac EXITCODE=0`；护栏计数；jar 自检；自测脚本的断言）。
- **反证**（修 bug 必填）：去掉修复能复现、装上修复不能复现（或用例 FAIL→PASS）。
- 未做的验证要写明（例如"未部署、未跑专服回归"）。

## 验收（谁说了算：开发者 —— `WORKFLOW.md` §4.1）
- 状态：`未验收` / `已验收@日期`（谁验的 / 怎么验的 / 证据：日志行 · 命令 · 截图）。
- 未验收之前：**不写 changelog、不写 release 说明、不发平台**（可以装进自己机器试）。

## 边界（没动什么）
- 明确列出本轮**没有**碰的东西（其它 issue 的点、已知差异、暂不改的债）。

## 台账
- 本轮清掉的债：`BD-xx` / `TD-xx`；新增的债与理由；配额是否满足（`WORKFLOW.md` §8）。
