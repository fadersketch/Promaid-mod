## 取证（玩家 17:08–17:10 日志 + 存档区块）

- 直接解析 `saves/新的世界/region/r.-1.0.mca` 的区块方块状态：
  **(-415, -60, 446) 是 `minecraft:campfire`，`lit=true`，四个槽位全空**，周围 64 格内
  没有其他营火、也没有熔炉/高炉/烟熏炉。
- 同一份日志里 `17:09:55 cook start: ... furnace=BlockPos{x=-415, y=-60, z=446}`——
  绑的就是这座营火（旧日志的 `furnace=` 字段名有误导性）。
- 时间线：`17:09:54` 玩家把女仆绑到直升机 → `17:09:55` 她绑上台（营火）→ `17:09:57`
  已经跟着玩家起飞。营火四槽始终为空：**她不是没认出来，是被载具带走了，没有落地做饭的机会**。
- 另一个真实的体验问题：`start` 在骑乘状态下也会选台——台被"带走"后，落地前一直挂着
  一个几十格外的台；复检失败又只在特定分支写日志，看起来就像"完全无视营火"。

## 改动（仅 Forge 1.20.1）

- `MaidCookBehavior.start`：骑乘中（`maid.getVehicle() != null`）直接返回，不选台；日志
  `cook start: ... 骑乘中 → 先不选台（落地后再找）`。
- `MaidCookBehavior.tick`：骑乘中释放已有台（`releaseFurnace` + 清 `furnacePos` /
  `stationCampfire` / stationLock / still），落地后由原有扫描重新绑定。
- 绑定成功（`tick` 的 `furnacePos == null` 分支）与从炉子迁到营火（R1104 分支）后
  `this.cooldown = 0`：绑定后下一拍就做第一轮，不再等最多 5 秒的处理间隔。
- R1104 复检失败分支：先清 `nearestLitCampfire` / `nearestAnyCampfire` 再扫，
  然后调用 `logScanWhy`——绑着炉子时也会写一次"为什么没用营火"（同状态只写一次）：
  附近有没有营火、点着没有、距离、工作区内外、四位满没满。
- `cook start` 日志改为 `台=营火/炉子 + 坐标`，不再把营火也写成 `furnace=`。
- **1.21.1 树未改动**（玩家确认那边无问题）；R1130 的两树镜像保持原样。

## 验收

1. 1.20.1 单人，女仆做「烧制」、背包有生肉、旁边点着一座空营火（开关开）：她走到营火旁
   邻格，坐下后**立刻**把肉摆上去（不再等 5 秒）。
2. 先让她绑上炉子，再在 16 格内放一座空营火：2 秒内日志 `cook switch: ... 从熔炉迁去营火`，
   她迁过去并立刻摆料。
3. 把她绑到直升机再起飞：日志 `cook start: ... 骑乘中 → 先不选台`；落地后她重新找台
   （营火优先），不会挂着一个远在基地的台。
4. 营火离得太远/没点着/四位全满时：日志出现一次 `cook scan: ... 点着的营火=...`，
   直接说明是哪一条不满足。
