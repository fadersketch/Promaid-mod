## 反馈原文

> 1.女仆在乘坦克接敌时还是有问题，应改为在接敌时无视与主人距离太远就停的那道闸
> 2.当女仆开固定翼飞机时退出游戏重进，飞机移动会彻底失衡

中途补充：

> 重点在于，女仆处于接敌状态下一旦主人离远就停下不动。玩家就会在一远处看到女仆坦克不动只有炮管在打怪。

> 将平时的跟随闸从50改为100

## 根因

### 1. 坦克"只有炮管在打、车不动"

R1077 只是把接敌绳从 50 提到 `GROUND_ENGAGE_LEASH = 192`，闸本身仍在：
主人超过 192 格，`gfoe` 被清空 → 地面载具分支落回"跟着主人"的兜底，车停在原地；
而 `tickAttack` 在更早的位置已经跑过、炮塔照常瞄准开火——玩家看到的就是"坦克不动，
只有炮管在打怪"。这与反馈逐字吻合。接敌状态下不应再拿主人距离当停止条件。

### 2. 固定翼退出重进后"彻底失衡"

实机日志（1.21.1 NeoForge，08:25:45 重新绑定固定翼，08:25:53 起飞）：

```
08:25:53  跟随档  鼠标X=12  滚转=45   水平速度=0.80
08:25:58  跟随档  鼠标X=12  滚转=-15  水平速度=0.80
08:26:03  跟随档  鼠标X=12  滚转=176  水平速度=0.80
08:26:08  接敌档  鼠标X=-12 滚转=132  水平速度=0.80
08:26:33  接敌档  鼠标X=12  滚转=-170 水平速度=0.60
08:26:38  接敌档  鼠标X=0   滚转=90   水平速度=0.60
```

滚转早就该被引擎 `aircraftEngine:826` 的 `ClampRoll` 钳在 ±45。反编译有两个关键事实：

- `ClampRoll` 的**代码默认值是 514**（`EngineInfo$Helicopter` 构造器实证），具体机型靠
  数据覆写；没有覆写或覆写到 180 的机型等于没有 45° 上限。
- 引擎的滚转来源是**左右位 → `deltaRot` 积分**（`:782-789`、`:819-826`），而这段积分
  **不受 `ClampRoll` 之外任何"目标 45°"约束**。我们巡航时为帮助转向一直送左右位，
  长时间同向转弯（重进后的第一段大转弯正是这种情况）就会每拍 +1.9° 一路累过 45°，
  到 176° 后 `baseTick` 再按 ±180 回绕成 -170°。滚转越大，
  `rotSpeed = 0.3 + 3.2*|roll|/90` 越大（176° 时约 6.5，是 45° 时的 3.4 倍），
  偏航角速度随之爆表——这就是"彻底失衡"。
- 我们的 `aircraftBank` 只把**目标**设为 ±45，却把 `cur + step` 原样写回，
  **从不钳结果**；当引擎把 roll 推过 45° 后，它只能以 2°/拍慢慢往回拧，压不住每拍
  1.9° 的积分。
- 叠加因素：`AIRCRAFT_CLIMB` / `AIRCRAFT_LAND_*` / `DIVE_UNTIL` 等缓存都按载具 UUID
  静态保存，退出到标题再进世界时 JVM 不重启、UUID 不变，旧计划会跨存档残留。
- 另有一处重载自愈缺陷：链路表里失效条目用 `deferred.add(null)` +
  `releaseMaidQuiet(null)` 清理，清的是 **null 键**，UUID 条目永远留着；重进后
  `restore` 看到 `LINKS.containsKey(UUID)` 为真就不重建链路。

## 改法（两树）

### A. 接敌时不再看主人距离（`RideBindManager`）

删除地面载具分支的整段闸：

```java
// 旧
if (gfoe != null && maid.distanceTo(owner) > GROUND_ENGAGE_LEASH) {
    gfoe = null;
}
```

`GROUND_ENGAGE_LEASH` 常量一并删除。接敌的起止只由目标是否存活/是否在索敌半径内决定；
"主人不在场就收手"只保留给飞行载具（见 C）。

### B. 滚转硬限幅 + 重进自愈（`MaidMountCompat` / `MaidAirCombat` / `RideBindManager`）

- `aircraftBank` / `aircraftBankLanding`：
  - 读到的 roll 先 `wrapDegrees` 归一；
  - `|roll| > 60°`（已经翻过去）→ **直接写 0 摆平**，不再慢慢拧；
  - 写回值 `next` **硬钳在 ±45°（降落 ±10°）**，即使引擎刚推到 46° 也这一拍压回；
  - 旧版只钳目标、不钳结果，是这次滚转外溢的直接原因。
- `aircraftCruise` / `holdAircraftPattern` / 旧式降落：只有反射拿不到滚转写口时
  才继续送左右位；能直写滚转时**不再送**，从源头切断 `deltaRot` 积分。
- `RideBindManager.bind` / `restore`：重建链路时调用
  `MaidMountCompat.resetAfterTeleport(mount)` + `MaidAirCombat.clear(maid)` +
  `MaidAirCombat.forgetMount(mount)`，清跑道/爬升窗口/助跑带/悬停机头/俯冲段等按
  UUID 残留的状态。
- `RideBindManager` 服务器 tick 的失效链路：改成 `it.remove()` **按 key 移除**，
  再对仍存活的女仆做一次静默释放；重进后 `restore` 能正常重建。

### C. 平时跟随闸 50 → 100（`MaidMountCompat.FLY_ENGAGE_LEASH`）

新增 `FLY_ENGAGE_LEASH = 100.0`，非固定翼飞行载具（直升机/飞艇/扫帚）的
"主人超出接敌半径 → 放弃敌人"闸从 `FlightTargeting.RANGE`（50）改用它。
索敌发现半径本身仍是 50，两者不再互相误伤；固定翼继续用 `AIRCRAFT_ENGAGE_LEASH = 450`。

## 验收

- 坦克：主人骑在远处（>192 格）时，日志仍应出现
  `接敌 → 开着地面载具绕着敌人转圈`，车保持绕圈；不应再出现"只有炮塔转"。
- 固定翼：退出重进后重新绑定，`固定翼巡航档` 日志里的 `滚转` 应始终在 -45~45；
  不应再出现 90/132/176 这类值，飞机不再连续翻滚。
- 直升机/飞艇：主人在 50~100 格内仍应继续接敌，不再中途脱战。

## 边界 / 已知取舍

- 地面载具接敌完全不受主人距离约束：极端情况下她会追着敌人跑很远（目标丢失/死亡即回归）。
  这是玩家明确要求的"接敌时无视那道闸"。
- 滚转越界采用"直接写 0"而非平滑回正：一次大跳变好过连续翻滚；正常飞行不会触发
  （只在新旧状态错位/引擎积分越界时）。
- 100 格只放宽"接敌保持"闸，不改索敌发现半径（仍 50）。
