## 评估
- **跑道**：A（P1：功能失效，玩家的主要照明手段失灵）。
- **复现（静态推演，附行号）**：
  1. `MaidTorchPlacerBehavior.tick` 的暗格扫描读**世界真实方块光**（L94-96：`max(block, sky - skyDarken)`，`light < darkest`，`darkest` 初值 = 阈值 7）。
  2. 她手上只要有光源（火把 14 / 灯笼 15…），`MaidHeldLight` 就在**她脚底**放一个 `minecraft:light` 光块（`MaidHeldLight:127`）；她跟在主人身边（≤8 格）时，主人的 **5×5 判定区全被她这个光块照到**（火把 14 → 区内方块光 7~14）。
  3. 于是 25 格全部 `light ≥ 7` → `target == null` → L103-105 **直接 return（"周围够亮"）→ 一根都不插**；把火把**放进背包**（手上无光源）→ 光块撤除（`MaidHeldLight:117`）→ 同一地点方块光回到 0 → 照插。
  4. 即：**"手上有没有光源"确实左右插不插**（方向与直觉相反：手持光源 = 不插），而**包里的火把本来就能用**——`findTorch`（L226-249）背包优先、`MaidExtraContainer.pull` 还先问精妙背包；全树 grep（`inHand/handOnly/手持/主手 or 副手`）**不存在任何"必须手持才插"的闸**（`combat.torchPlacerEnable` 之外那条链的 `hasLightItem` 也是"背包∪额外容器∪双手"三处都认）。
  5. 这与 `MaidHeldLight:25-27` 自称的「【不影响插火把】……插火把判定零改动」**互相矛盾**——判定的确没改，但**光块的加入改了世界亮度**，副作用就是这条链路被她自己静默关掉。原始需求原话（同文件 L11-12）要的正是"不影响"。
- **根因②（同轮发现的另一条真缺陷，同一条 return）**：扫描只取**唯一最暗**的那一格（L97-102 严格 `<`），随后 L107/L112/L119 三道可用性判定任一不过就 `return`——**不会去看第二暗的格子**。矿道贴墙/家具多的地方，最暗格常是墙体/箱子/被主人占的格 → 整轮放弃。这是"她在这地方永远不插、在别处偶尔插"的地形相关性来源。
- **同类点清单与处置**：① `MaidSpawnerTorchBehavior`（防刷怪插火把）同读世界光——她站在笼边举着火把会让"这只笼已经点过了"误判 → **一并修**；② 两条链路的 `BombPose.showGated`（副手举一下的"拟真"表现）→ **删**（开发者："不再要求原来的拟真行为""不再要求对火把在手和包的位置进行变动"）；③ 其余链路（搭路/建造/种植…）的 `BombPose` **不动**（那是另外几轮的既定交付）。
- 查过 `ARCHITECTURE-SWITCHES.md` / 债务台账：无等价开关、无既有债。

## 改法（已实施）
1. **`MaidHeldLight` 新增两个只读判据**（两树）：
   - `envBlockLight(maid, level, pos)`：返回该格的"**环境**方块光"——把她自己那个光块**可能贡献的亮度上界**（`光强 − 曼哈顿距离`）减掉；该格方块光 ≤ 这个上界（= 这一格的亮可能全部来自她自己）→ 按 **0** 算，否则原样返回。天光那一侧不参与（仍由 `getSkyDarken` 管）。零写入；她没光块时逐字节等于原读取。
   - `isOwnLightBlock(maid, level, pos)`：这一格是不是她自己那个隐藏光块（给防刷怪去重用）。
   - 类注释里那段自称"【不影响插火把】……判定零改动"改成新口径（原来那句话与事实不符）。
2. **`MaidTorchPlacerBehavior`（被动插火把）**（两树）：
   - 扫描改为"**在 25 格里挑最暗的、真能放下的格**"：三关（空气 / 不被主人撞箱占 / 脚下有支撑）**前移进循环**，最暗那格放不了就看第二暗的——旧版只取唯一最暗格、拿到后才判三关，任一不过就整轮 `return`。
   - 亮度判据改走 `MaidHeldLight.envBlockLight(maid, level, p)`。
   - **删** `BombPose.showGated`（副手举火把的拟真表现）与只服务于它的 `torchShow` 快照；**保留**"放下 → 扣 1 根（`extractOneHonest`，扣不到就把刚放下的拆掉回滚）→ `swing(MAIN_HAND)` 一次"；**不搬动任何槽位**（背包含精妙背包优先、主/副手兜底——原样）。
   - 新增限频留痕（搜「插火把」）：`noTorch`（背包/精妙背包/双手都没有）、`noSpot`（有 N 个暗格但一个都放不了）；状态变化立刻记、同结论 10 秒内不重复。
3. **`MaidSpawnerTorchBehavior`（防刷怪插火把）**（两树）：
   - `stillNeedsTorch` 拆两版：带 `maid` 的版本把她自己脚底那格光块排除在"这只笼已经点过了"的去重之外（她站在笼边时脚底光块会落进候选位，旧版据此认为笼子已处理 → 永远不插）；`maid == null` 的版本不排除任何光源，**照旧给 `spawnSkipReason` 用**（那里判"这地方是不是被光照压住了"，她举着的火把是**真实光照**，压住笼子这件事本身成立）。
   - **删** `BombPose.showGated`，保留 `swing` 一次与扣料/回滚；`show` 快照改为只留日志要用的名字。
- **被否掉的方案**：见上（不动 `MaidHeldLight` 的照亮功能 / 不给 DIY 表添新闸 / 不引入"必须手持"开关）。
