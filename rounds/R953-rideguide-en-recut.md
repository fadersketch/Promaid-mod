## 症状 / 现场（改前）

`GuideScreen.translateParagraph` 是**按整段**（`paras` 里一个元素 = 一个键）查表的：
`PromaidI18n.tr(raw)`。而 `rideGuide()` 这一章的英文 value **不是按中文段落边界切的**——
每个 value 的首/尾错落到相邻条目上，于是英文客户端读到的是「上一段的后半句 + 这一段的前半句」：

| 元素 | 中文键开头 | 错位后的英文开头（改前） |
|---|---|---|
| [5] | 能不能骑… | `Can ride?…`（**缺**"无鞍可骑仆从"那一段，尾被截在 `…to be a player, so `） |
| [6] | 这类仆从骑上之后… | `Saddle-free rideable servants…`（这是 [5] 的第二段） |
| [7] | 主人空手右击… | `don't need a saddle…`（这是 [5] 第二段的尾 + [6] + [7] 三段的合体，2224 字） |
| [17] | 守家对飞行载具也生效… | `Home mode also applies to flying vehicles§r: `（只有 47 字，尾在 [18]） |
| [18] | 骑乘时她的寻路… | `homed flying vehicles hover in place…`（这是 [17] 第一段的尾） |
| [21] | 【横扫之刃】【坐龙俯仰】【没电的载具】 | 只到第二段，**第三段整段漏到 [22] 里** |
| [22] | 默认档… | 开头压着 [21] 的第三段（"没电的载具不能起飞"） |
| [29]–[38] | 卓越前线 / 固定翼 / 投弹 共 10 条 | 整族**滚动错位**（每条的英文都比它自己的中文晚/早一段） |
| [32] | 投弹间隔 2 秒 / 主炮弹种表 / 投弹安全高度 | value 是 [31] 的两段；**前两句中文全表**、**无英文** |
| [33] | 四架固定翼… | 只剩"汤姆 F6F / 迷你快艇"那句；四架固定翼本段在 [35] |
| [66] | 坐在龙上怎么都下不来… | 尾部被截在 `…will move her, and §`（后两行无英文） |

另有小标题 bug：`七、固定翼全都能开了` 在两树源码里**丢了 `§e…§r`**，而词条表里存的是
`"§e七、固定翼全都能开了§r"` —— 键对不上 → 英文客户端这一行回落成中文（表里其实早就有译文
`§e7. Every fixed-wing can be flown now§r`）。

## 核真值（怎么定位的）

- `tools/_seg.py` / `_r953.py` / `_d953.py`：把 `rideGuide()` 的 67 个 `paras` 元素解出来（`\uXXXX` 解码 +
  `+` 拼接），逐条打印中文段落与表里现有英文 → 肉眼可见错位。

  `calculateFiringSolution`…）必须在英文里出现；命中 7 条，与人工定位的错位族**完全吻合**（互证）。
- `_rep.py`：打印受影响条目的**精确 `repr`**（看清 `\n` 与段落分隔），据此写「按标记切 + 断言唯一命中」
  的手术脚本，不靠猜。

## 改法（两树镜像；只改 value，键不动）

1. **重切 18 条 value**（`assets/promaid/i18n/en_us.json`）：`[5][6][7][17][18][21][22][29]…[38]`（src 的 [66]
   = neo 的 [59]，同键），把英文流按**中文段落边界**重新切开，每段归位。切法全部走唯一标记 + 断言，例如
   `[5] = v5 + "\n\n" + v6 + v7[:"§eOnce mounted"]`。
2. **补译 4 处缺失英文**（原表里根本没有）：
   - `[32]` 第 1 句：投弹两发至少隔 2 秒（基洛夫弹匣 7 / 爆炸半径 42 / 飞船挨航空炸弹 3 倍伤害）。
   - `[32]` 第 2 句：主炮弹种表（穿甲 / 高爆 / 霰弹），打不响换同门炮有弹的弹种，全无弹写
     「模组坐骑·缺弹」→ EN `「Mod Mount · Out of Ammo」`。
   - `[66]` 第 3 行尾续：特殊载具上只有排班表手动传送能叫她、只传人不传载具、传送即解绑。
   - `[66]` 第 4 行：`latest.log` 搜「骑乘指挥棒」一行行写什么，以及载具驾驶/飞行档的日志关键词表。
3. **小标题补 `§e…§r`**：两树 `GuideChaptersCombat.java` 里把 `"\u4e03\u3001…\u4e86"` 改成
   `"\u00a7e…\u00a7r"` → 命中表里既有译文，无需新增词条。
4. 顺手修复用英文里的语法：`so this mod don't drive this tick` → `doesn't`；`this mod don't touch` → `doesn't`。
5. **两树词条表都改**：先核「哪些键两树相同」——`rideGuide()` 第 [0]…[39] 元素两树一字不差（同键同旧值），
   故同一套手术脚本可跑两树；两树改出的长度逐条相同（如 [5] 244→684）。
6. **清掉同一条被 R919（汤姆 F6F / 迷你快艇解禁）推翻的旧断言**「§e仍不开的两台§r：汤姆 F6F / 迷你快艇——…」
   （R952 只删了它的**兄弟句**"自动解绑"，漏了这句）：
   - 两树各有一条**历史死键**（整章老页键，src 2594 字 / neo 4349 字）里同时写着 zh 与 en 两版旧断言
     → zh 换成真值、en 也换成真值（与已被 R952 修正的「其余载具一律不受影响」那句对齐）。
   - neo 的 **live 条目**「坦克主炮射速兜底」（`rideGuide#46`）里也混进了同一段 → 删掉那两段旧断言
     （只删不加译；删完该条的 value 正好等于它自己的英文）。
   - 改后两树搜 `still not drivable` / `auto-dismount` 均 **0**。
