## 评估
- **这条"取下"是哪条路**：当前技术栈里能把她副手物取下来的只有**女仆界面（装备/手持页）的容器取出**（装了鼠标手势类模组时 shift+右键 = 快速移动，就是粉丝说法的来源）。世界里对女仆的 shift+右键交互都不是取物：TLM 侧是换坐姿 / 下坐骑 / 好感度工具 / 精妙背包抽经验（javap：`SwitchSittingEvent`、`DismountMaidEvent`、`UseFavorabilityToolEvent`、`sbackpack.BackpackRightClickMaidEvent`），本模组侧没有新增该交互（全树 `m_6144_` 只命中自保/手册两处无关代码）。
- **历史根因（三条，全部已清）**：
  1. **BD-12（P0，最贴近本反馈）**：「把女仆身上穿戴的装备拖进玩家物品栏时装备直接消失」——旧「装备救回」是**当拍快照**判定：玩家把装备拿起时它在光标上 → 当拍不救；可随后放进背包那一下万一真丢了，`LivingEquipmentChangeEvent` 只在"有→空"补发一次、**不会再来第二枪** → 永久消失（那一局日志 58 条 `[装备离开]` / **0 条 `[装备救回]`**）。**已清@实测八百六十六**：改成"穿戴装备托管"——离身即打标记，每 5 拍定位一次，只有确认落到最终位置（她的容器/装备槽、任意玩家背包或当前界面、附近掉落物、别的女仆）才销；只要还在光标上就续期不清；到点 1.5 秒四处查无才放回她身上、**任何路径都不删**。
  2. **BD-10（P1）**：玩家从女仆界面取走副手物被"救回"塞回来（刷物品）——旧判据 `isPlayerDriven` 看调用栈，而该事件是实体每 tick 补发的、栈里永远没有菜单/网络帧 → 判据恒 false。**已清@实测八百四十一/八百四十三**（改查"任意玩家的光标与背包是否持有该件"；"是不是同一件"改成**去掉耐久后**完全相同，并把她**两只手**也纳入"还在她身上"的判据）。
  3. **BD-11（P1）**：拆刷怪笼借镐的"没还回去 + 背包多一把"——旧版把摘下的副手原物只存在**内存字段**（WeakHashMap 键还是旧实体实例），跨维度传送/世界重载换实体后那些事件让副手那件**彻底消失**（玩家实测丢过盾牌、剑、靴子）。**已清@实测八百二十六/八百二十七/八百三十三**：原件改存**她自己的持久 NBT**（`promaid_torch_saved_offhand`）+ 每轮补一道 `recoverSavedOffhand`。
- **"进食时更容易触发"解释得通（在旧版上）**：TLM 的进食任务（`MaidHealSelfTask` / `MaidHomeMealTask` / `MaidWorkMealTask` / `MaidBreathAirTask`）在开吃时会**把手上那件（主手/副手都可能）挪进她的隐藏格**、把食物放进手，吃完再还原；隐藏格原来有东西时**旧内容会被丢在她脚下**（javap 实证 `EntityMaid.memoryHandItemStack`）。于是"她正在进食"这段时间手槽吞吐最频繁——旧版那套"当拍快照 + 只看一次"的救回/判丢正好在这个窗口里最容易判错：判"没丢"就是真丢（BD-12 形状），判"丢了"就是复制（BD-10/11 形状）。
- **当前版本（1.3.2 线）这条路的保证**（本轮逐条复核源码）：
  - 她的手中/副手的**真写点只有三处**：拆笼借镐（原物持久 NBT + 补收）、种植"主手⇄副手换手"（原物**物理放进副手**，不靠内存）、姿态展示（`BombPose`/`FlightFireworkPose` 已改**只发客户端装备包**，服务端一个字节不碰；旧版 `setItemInHand(OFF_HAND, …)` 留在注释里当反面教材）。
  - 取材/投喂链一律**跳过"被借走的副手"**（`MaidBuildBlockFilter.OFFHAND_HAND_SLOT` + `BombPose.offhandBorrowed`），投喂她手上那件前会**再核对一次当前手**才结算。
  - 取走后的兜底：托管只在**确认四处查无**后放回、**绝不删**；食物/药水/烟花/桶/耐久见底**不纳入**（吃掉的最后一件、用坏的盾不会被"救回"成复制）；"她身上还有"（背包/隐藏格/任务格/饰品/**两只手**）即认落定。
  - 结论：**当前版本这条路上找不到"丢失"路径**（能构造出的最坏情况是反向的"多一件"，见下）。
- **唯一残留边界（本轮登记）**：托管定位器看不见"玩家背包里**容器物品的内袋**"（精妙背包/潜影盒这类，袋内容不在 `containerMenu.getSlots()` 里）。玩家若在 1.5 秒窗口内把取走的装备塞进这种内袋 → 判查无 → 到点放回一件 = **复制方向**。已记 **BD-25(P2，未清)**，附两个候选修法（定位器认两种内袋 / 到点放回改二次确认）。
- **要粉丝补什么**（拿到就能定性）：① 模组版本号（`promaid-1.3.2-*.jar` 文件名或手册里的版本）；② `promaid.log` 里该次操作前后 30 秒的 `[装备离开]` / `[装备托管]` / `[装备救回]` 三行（当前版本这三种行就是为这条链路留的证据）；③ 是否装了鼠标手势类模组（shift+右键 = 快速移动的来源）；④ 取的是**副手**还是**主手**、那件是什么。
- **级别**：本轮无代码改动；残留边界 **P2**（复制方向、需玩家主动塞内袋）。
- **风险**：无（文档/台账改动）。
